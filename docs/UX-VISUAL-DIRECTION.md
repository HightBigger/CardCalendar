## 1. 目标与判断标准

Cardfolio 是高频个人金融运营工具，不是营销页、投资终端或游戏界面。用户打开页面的目的通常是快速回答三个问题：现在最应该处理什么、这条规则是否可信、完成后会留下什么记录。因此“科技感”必须服务于状态识别、信息追溯和操作反馈，而不是增加装饰密度。

本轮视觉评审以以下标准判断：

- **一眼可分级**：临期、待核对、已完成和普通信息在 1 秒内可区分。
- **数据可扫描**：任务、积分批次和日期在窄屏上仍使用稳定的列与数字层级。
- **可信而克制**：规则来源、最后核对日期和证据等级有固定位置，不用光效伪造可信度。
- **材料有边界**：半透明只承载结构性 Chrome（侧栏、顶栏、浮层、抽屉），核心数据表面保持实心。
- **反馈可恢复**：动作有即时状态、可撤销或明确的处理中状态；动效不阻塞高频操作。

## 2. 方向比较与决策

### A. Apple / Liquid Glass Light

**视觉语言**：暖白或冷白画布、低饱和系统色、半透明顶栏和侧栏、柔和阴影、细分隔线、较大的留白。透明材质用背景模糊和亮边表达空间层级，内容层以白色实心表面承载数据。

**优势**：长时间使用舒适；适合个人财务的安静、可信气质；对中文正文和打印场景友好；`prefers-reduced-transparency` 可以自然退化到不透明表面。

**风险**：在活动截止、积分批次和任务进度同时出现时，状态色容易显得过轻；如果继续堆叠白色卡片，会回到当前“中性后台”问题；半透明在浅背景上的层级差异需要非常精细的光照边缘。

**适合使用**：默认浅色模式、账单核对、表单录入、打印/导出和视力敏感用户。

### B. AI Operations Command Center Dark

**视觉语言**：石墨黑画布、蓝灰不透明数据区、结构层的轻度透明和模糊、细线网格、等宽数字、青蓝行动色、琥珀/珊瑚风险色。信息组织借鉴 AI 产品的 command palette、任务收件箱、来源置信度和实时状态条，但不使用会误导用户的“智能预测”措辞。

**优势**：状态对比强，时间线和进度在首屏更容易形成操作焦点；深色背景能让来源标签、批次到期和任务进度成为明确的视觉信号；对工作台和详情检查器有较强的空间感。

**风险**：长时间阅读大段中文会疲劳；发光、扫描线或动态背景会把工具变成游戏化仪表盘；透明层过多会降低表格和低对比文字的可读性；打印和高对比模式需要单独退化规则。

**适合使用**：工作台、提醒队列、活动/任务执行和积分到期监控。

### 决策：B 为主、A 为可切换的语义主题

工作台首版采用 **B 的石墨指挥台骨架**，因为它能更快传达“现在该行动什么”，并为活动、权益、刷卡任务和积分增加稳定的状态层。A 不被放弃，而是作为同一语义 token 的浅色主题和无障碍降级路径：组件结构、间距、状态名称和来源信息保持一致，只改变画布、材料和边界色。

这个取舍不是全站深色玻璃化：

1. 侧栏、顶栏、移动抽屉和弹出面板是唯一允许透明/模糊的结构层。
2. 指标、任务列表、时间线、积分批次表和表单使用 `--surface-solid` 或 `--surface-raised`，不把每一行变成玻璃卡片。
3. “科技感”来自清晰的状态协议、细线层级、数字排版、来源/新鲜度信息和短促反馈，而不是全屏渐变、粒子或闪烁动画。

## 3. 视觉 Token

### 3.1 颜色

深色主题 token（原型使用）：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#0b1118` | 页面底色，带极弱网格纹理 |
| `--surface-solid` | `#111b25` | 任务表、列表、指标的实心表面 |
| `--surface-raised` | `#172330` | 当前选中或需要更多层级的面板 |
| `--chrome` | `rgba(12, 20, 29, .78)` | 侧栏、顶栏、浮层 |
| `--line` | `rgba(150, 180, 202, .16)` | 结构分隔线 |
| `--text` | `#edf5f8` | 主文字 |
| `--text-secondary` | `#a9bac5` | 辅助说明 |
| `--text-tertiary` | `#718694` | 时间、单位和弱提示 |
| `--accent` | `#54d6e8` | 主行动、链接、当前进度 |
| `--accent-strong` | `#1da8c0` | hover、焦点、选中边界 |
| `--success` | `#55d39a` | 已达标、已完成、可用 |
| `--warning` | `#f2bd68` | 7/30 天临期、待核对 |
| `--danger` | `#ff817c` | 已逾期、失败、争议 |
| `--info` | `#91b9ff` | 一般信息、官方来源 |

浅色主题映射（A）：`--canvas: #f4f6f8`、`--surface-solid: #ffffff`、`--surface-raised: #eef3f6`、`--chrome: rgba(247,250,252,.78)`、`--text: #16222b`、`--text-secondary: #50616d`、`--accent: #087f9d`。状态色保持语义不变，并在浅色背景上加深文字色。

不使用纯黑/纯白作为大面积背景；不使用紫色渐变作为默认品牌识别。青蓝只作为行动焦点，不能给所有标题和边框上色。

### 3.2 材质与层级

| 层级 | 视觉处理 | 组件 |
| --- | --- | --- |
| L0 画布 | 实色 + 低频 1px 网格，静止 | 页面背景 |
| L1 数据面 | `--surface-solid`，1px 低对比边界，最多 8px 圆角 | 指标、任务表、时间线、积分批次 |
| L2 提升面 | `--surface-raised`，左侧或顶部状态线 | 当前任务、异常面板、详情检查器 |
| L3 Chrome | `--chrome` + `backdrop-filter: blur(18px) saturate(130%)` + 内亮边 | 侧栏、顶栏、浮层、抽屉 |
| L4 重点 | 仅用状态色 2px 轨道/小型光晕，不扩大表面 | 进度、待处理计数、焦点操作 |

透明度采用 0.72--0.86 的窄范围；核心内容不依赖背景透出才能阅读。`prefers-reduced-transparency: reduce` 时所有 L3 退化为实色，保留边界和阴影。

### 3.3 字体与数字

- 首选系统字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 主标题 28--34px，行高 1.12；面板标题 15--17px，行高 1.3；正文 13--14px，行高 1.55；辅助信息 11--12px，行高 1.4。
- 中文正文 `letter-spacing: 0`，小号辅助文本最多 `0.02em`；不全局负字距。
- 金额、积分、日期和进度百分比使用 `font-variant-numeric: tabular-nums`，方便纵向比较。
- 标题使用 650--720 字重制造层级，不用超大 hero 字号。

### 3.4 间距、圆角与边界

基础间距为 4 的倍数：`4 / 8 / 12 / 16 / 20 / 24 / 32`。桌面内容最大宽度 1280px，侧栏 248px；移动内容左右内边距 16px。普通表面圆角 6--8px，浮层 10--12px，避免胶囊化和卡片套卡片。焦点环使用 2px `--accent` 外环，不能只依赖颜色改变。

## 4. 信息架构到视觉结构

侧栏保留六个稳定入口：**工作台、卡片、活动、权益、积分、提醒**。刷卡任务是活动的分段视图，也是卡片详情和工作台队列的可执行对象，不增加第七个一级入口。

桌面工作台的首屏顺序：

1. 顶栏：当前页面、全局搜索、日期/同步新鲜度和账户入口。
2. 头部行动区：本日问候、90 天窗口、快速新增菜单和规则核对状态。
3. 待处理轨道：按紧急度排序的任务/到期对象，显示“下一步动作”和来源可信度。
4. 任务与时间线：左侧是活动/刷卡任务列表，右侧是未来 30 天事件时间线。
5. 资产摘要：卡片、权益和积分批次使用紧凑列表，下钻至详情。

移动端不复制桌面双栏：顶栏保持 52--60px，侧栏变为带遮罩的抽屉；待处理队列和任务列表单列；时间线改为按日期分组的垂直轨道；指标从四列改为横向可滚动的两列网格；浮层从底部抽屉进入且保留安全区。

## 5. 关键组件与状态

### 5.1 待处理队列

每项固定显示：对象类型、标题、关联卡片、截止日/剩余天数、当前值与目标值、下一步动作、规则可信度和最后核对日期。超过 30 天的普通事项降低亮度，但不隐藏来源信息。

### 5.2 任务进度

使用实心轨道 + 2px 青蓝进度线。进度线不使用连续动画；用户更新后只做一次 160--220ms 的宽度过渡。显示 `¥12,000 / ¥20,000` 或 `4 / 6 次`，并单独显示 pending（待入账）和 disputed（有争议），避免把预估消费当成已达标。

### 5.3 规则来源与新鲜度

来源等级用小型标签而非大面积颜色：`官方已核验`、`官方页面但信息不完整`、`用户自录待核对`。最后核对日期距离当前超过阈值时，增加琥珀点和“请核对官方规则”，不自动改变用户数据。

### 5.4 积分批次

积分账户表以账户为主行、到期批次为次行；使用等宽数字和日期列。批次临近时在行首加 2px 琥珀轨道。兑换结果使用状态 chip，展示所需积分、现金附加金额、处理时间线和来源，不显示未经确认的“最佳兑换”。

### 5.5 动效

| 场景 | 动效 | 参数 |
| --- | --- | --- |
| 按钮按下 | `scale(.98)` | 120ms ease-out |
| 侧栏/抽屉 | 位移 + 透明度，保持可中断 | 220ms `cubic-bezier(.32,.72,0,1)` |
| 浮层出现 | `scale(.97) -> 1` + blur 增强 | 180ms ease-out |
| 进度更新 | 只更新轨道宽度 | 180ms ease-out |
| Toast | 从触发点方向 materialize | 180ms ease-out |

不使用循环扫描线、旋转粒子、背景漂浮光斑或超过 300ms 的高频交互动画。`prefers-reduced-motion: reduce` 时改为 80--120ms 颜色/透明度变化并取消位移；键盘触发的重复操作不添加动画。

## 6. 可访问性与退化路径

- 主文字与实心表面的对比度目标为 WCAG AA（正文至少 4.5:1，大号文字至少 3:1）；状态不能只用颜色，必须同时有中文标签或图标。
- 所有图标按钮提供中文 `aria-label` 和 hover `title`；焦点顺序遵循“顶栏 → 待处理 → 任务 → 时间线 → 资产摘要”。
- 触控目标至少 44×44px；移动端抽屉打开时锁定背景滚动，Escape 可关闭并恢复触发按钮焦点。
- `prefers-reduced-transparency: reduce`：L3 使用 `#111b25`/`#ffffff` 实色，取消 backdrop blur。
- `prefers-contrast: more`：边界提升至 `rgba(220,235,245,.42)`，状态色加深，取消低对比网格。
- `forced-colors: active`：使用系统 Canvas/Text/Highlight，保留文本状态和边框，不依赖阴影或透明度。
- 390px 宽度下禁止横向滚动；金额、中文标题和操作文字允许自然换行，表格转为标签化的行卡但保持列对齐。

## 7. 实现边界与当前落地

本规范已经落地到当前年费 MVP 的工作台壳层，但不代表未来活动、权益、积分和兑换功能已经实现。

已落地文件：

- `app/globals.css`：深色石墨画布、L0-L4 语义层、结构性半透明 Chrome、细网格、状态轨道、按钮按下反馈和 reduced-transparency/reduced-motion/forced-colors 退化。
- `components/mvp-app.tsx`：一级入口“工作台”、个人金融工作台副标题、状态优先的工作台标题和保留现有年费 MVP 交互/selector。

当前落地范围只覆盖真实年费 MVP 的壳层、卡片、年费日历、提醒和设置；UX V2 中的活动、权益、刷卡任务、积分批次和兑换内容仍是规划原型，不得当作已实现入口或实时 AI 能力。

正式实现阶段应继续复用语义 token 和壳层，不在每个页面复制颜色；新增领域组件必须遵守“透明只用于结构 Chrome、核心数据面保持实心、未知状态可行动”的边界。

实施顺序建议：

1. 先建立 light/dark 语义 token 和 L0--L4 层级；
2. 改造侧栏、顶栏、待处理队列与任务进度；
3. 将活动、权益、积分详情统一到同一检查器和来源/新鲜度组件；
4. 加入浅色主题、三种偏好退化和桌面/390px 浏览器验收；
5. 最后再评估是否需要任何轻量品牌位图，不为装饰引入图片依赖。

## 8. 待评审问题

- 是否将深色主题作为所有用户默认，还是根据系统外观自动选择并允许用户手动切换？建议首版跟随系统，工作台提供显式切换。
- 青蓝行动色在不同银行品牌色上是否需要用户自定义？建议暂不开放，避免状态语义被品牌色覆盖。
- 规则来源摘要是否需要折叠？建议桌面默认显示一行，移动详情展开后显示全文摘录和访问日期。
- 工作台是否需要“AI 助理”入口？建议后置，首版只使用可解释的筛选、排序和提醒，不暗示自动判断银行资格。

## 10. 真实页面复核结论（2026-08-15）

UX 角色基于运行时截图和当前实现复核后确认：深色默认可以保留，但产品语义应是“专注工作台”，不是实时终端；当前没有 AI、预测、在线或同步中的误导文案，也没有循环扫描/粒子动画。390px 指标已验证为 2+2+1 布局，移动抽屉、Escape、焦点恢复和新增卡片表单无横向溢出。

发布前的 P1 视觉工作项为：补充用户可控或跟随系统的浅色主题、在活动/权益/积分模块加入“来源等级 · 最近核对”行、用 320--360px 长中文和真实金额做走查，并继续保持静止网格和弱光晕，不引入实时遥测暗示。详见 [UX 角色复核台账](../coordination/role-sessions/ux-tech-workbench-v2/ledger.md)。
