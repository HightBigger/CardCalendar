## 1. 结论

真实应用已经不是浅色后台：它实际加载了深色石墨画布、青蓝行动色、实心数据面与半透明侧栏/顶栏。计算样式证实侧栏和顶栏均为 `blur(18px) saturate(130%)`，数据行背景为实心 `#111b25`。这符合“半透明只用于结构性 Chrome”的方向，视觉基调可以保留。

但当前产品**仍然是年费 MVP，而不是文档规划的信用卡工作台**：真实一级导航只有“概览、我的卡片、年费日历、提醒中心”，概览的唯一业务主线仍是未来 90 天年费与免年费进度。活动、权益、积分、来源可信度和规则新鲜度并未进入真实界面。因此，当前深色样式是正确方向的表皮，尚未形成 AI 时代工作台所需的可解释操作系统。

### 2.2 运行环境说明

`localhost:3000` 当时有两个 `next dev` 进程同时服务同一工作区。HTML 引用的 `_next` CSS hash 会被另一进程接到并返回 404，得到无样式的登录页。该端口不能作为视觉验收依据。本评审使用单独的 `3002` 端口；这不是产品样式问题，但本地启动说明应避免同端口多进程。

## 3. 当前实现评审

### 已成立的设计基础

- 深色 token 使用石墨画布、青蓝行动色、琥珀/珊瑚风险色和等宽数字，适合高频金融管理，而不是营销页。
- `sidebar` 与 `topbar` 的半透明层有明确范围；列表、指标、输入和模态保持实色，避免“全屏玻璃卡片”。
- 活动行 hover 只有 120--160ms 的背景、边框和 1px 位移；详情模态为 240ms opacity/transform。这是可打断的微反馈，而不是装饰性循环动画。
- 移动导航支持抽屉开关、Escape 关闭及焦点返回；390px 真实截图中没有横向滚动。
- 已存在 `prefers-reduced-transparency`、`prefers-contrast` 与全局 `prefers-reduced-motion` 退化路径，方向正确。

### 必须先修复的真实问题

| Before | After | Why |
| --- | --- | --- |
| 5 个 `.metric` 子项进入 `repeat(4, minmax(0, 1fr))` 网格，桌面和移动都留下孤立的“待办事项”单元格。 | 把顶层摘要重组为 4 个稳定指标；将“待办事项”升级为紧随其后的行动队列标题/总数，或让第 5 项在明确的整行布局中占满。 | 当前视觉把行动事项降格为一个孤立 KPI，并制造大面积无意义留白；工作台应以行动队列而非指标墙为中心。 |
| “总卡片”因 `.metric:first-child` 获得珊瑚色左轨。 | 仅对逾期、异常、待核对对象使用珊瑚轨道；一般资产数量使用中性色或青蓝信息轨道。 | 珊瑚是风险语义。总卡片数不是风险，错误的颜色映射会削弱风险提示的可信度。 |
| 卡片详情内“设置累计值”实际样式为白色背景 `rgb(255,255,255)` 和浅灰文字 `rgb(169,186,197)`。 | 活动分段的 active 项使用 `--surface-raised` + `--text`，非 active 项使用透明背景 + `--text-secondary`，两者保留 1px 可辨边界。 | 真实对比度不足，且白色块破坏深色 command-center 的材料一致性。根因是历史浅色 `.progress-mode-switch button.active` 与新 token 规则在长 CSS 文件中层叠冲突。 |
| 一级导航和概览仅覆盖年费：`概览 / 我的卡片 / 年费日历 / 提醒中心`。 | 按已批准 UX 架构迁移为 `工作台 / 卡片 / 活动 / 权益 / 积分 / 提醒`；刷卡任务保留为活动分段、卡片详情和待处理队列中的对象。 | 样式不能替代信息架构。没有活动、权益、积分与规则来源，当前界面无法支持工作台的核心承诺。 |
| 卡片详情是单个长模态，内部再滚动并承载录入、进度、事件历史和提醒。 | 新工作台的卡片详情改为可深链的主从详情页；模态仅用于新增、确认、更新一个短动作。 | 长模态切断上下文，移动端尤其难以回到任务来源；这也与已完成的 UX 工作台规范一致。 |

## 4. 科技感与 AI 工作台决策

### 4.1 保留：深色石墨，不增加炫光

继续使用石墨画布 `#0b1118`、实心数据面 `#111b25`、青蓝行动色 `#54d6e8`，但不要再增加渐变、扫描线、粒子、漂浮光球或持续发光。Cardfolio 的科技感应来自数字排版、可信度、新鲜度和任务状态，而不是“赛博装饰”。

### 4.2 材料协议：只有三个位置可用玻璃

| 层级 | 允许的处理 | 禁止的处理 |
| --- | --- | --- |
| 结构 Chrome | 侧栏、顶栏、移动抽屉：`rgba` + 18px blur + 细亮边 | 叠放两个半透明内容卡片 |
| 数据面 | 指标、任务、积分批次、表格、表单：实心表面 + 细边界 | 透明文字覆盖动态背景 |
| 浮层 | popover、sheet、modal：实心提升面、暗色 scrim、来源触发点的 180--240ms materialize | 用模糊代替对比度或在浮层中放重动画 |

`prefers-reduced-transparency: reduce` 必须让 Chrome 直接回退为 `--surface-solid` 并移除 `backdrop-filter`；当前已有该规则，正式实现活动/权益/积分页面时不可绕开。

### 4.3 AI 是“可解释操作”，不是聊天入口

首版不增加没有数据依据的 AI 助理或“最佳刷卡”承诺。AI 时代的界面应该先把以下可解释信号做成固定视觉语法：

1. **下一步动作**：报名、更新进度、预约、核对规则、记录到账。
2. **事实阶段**：已确认、待入账、待核对、争议、已过期。
3. **证据/新鲜度**：官方已核验、官方页面但信息不完整、用户自录待核对；最后核对日期和来源链接。
4. **影响范围**：关联卡片、活动时间窗、积分批次到期日、权益可用次数。

这样即使将来增加 AI 摘要，也只能解释“为何排序/为何提醒/引用哪条规则”，不能替用户判断个人资格、交易归类或兑换最优性。

### 4.4 工作台视觉结构

第一屏顺序固定为：

```text
风险与临期队列 -> 可执行刷卡任务 -> 未来 30 天时间线 -> 卡片/权益/积分摘要
```

顶层摘要最多 4 项，建议是 `待处理`、`进行中任务`、`即将到期权益`、`临期积分`。卡片总数和未来年费属于较低优先级摘要，不应挤占行动区。活动、权益、积分都必须拥有可下钻的实心列表行；来源和核对时间在行内稳定出现，避免依赖 hover 才可见。

## 5. 动效与无障碍验收结论

当前动画量处于可接受范围：行 hover 为 120--160ms，模态为 240ms，均低于 300ms。移动导航已验证 `aria-expanded` 和 Escape 路径。下一次实现必须追加 Chromium 媒体偏好截图，覆盖：

- `prefers-reduced-motion: reduce`：所有进入/退出只保留短透明度变化，取消位移、缩放和 hover 上浮；
- `prefers-reduced-transparency: reduce`：顶栏/侧栏不透明；
- `prefers-contrast: more`：列表、指标、模态和输入边界足够强，同时状态保留中文文本而非仅靠颜色；
- 390px：每个主按钮至少 44px，长中文标题可换行，金额和日期使用 tabular numerals。

注意：当前 `globals.css` 已经历多轮主题追加，旧浅色规则仍位于前段，新深色规则依赖后写覆盖。白色 active 分段控件正是这种层叠风险的实际证据。正式接入前应在一次受控重构中收敛为单一 token 层和单一组件层，避免继续追加主题补丁。

## 6. 交接优先级

1. **P0 视觉回归**：修复 5 项指标网格、总卡片珊瑚语义、详情分段白底低对比；重新拍桌面/390px。
2. **P0 信息架构**：真实导航和工作台页面进入活动、权益、积分、规则来源与待核对状态；不要把工作台 PRD 停留在文档中。
3. **P1 详情迁移**：长模态改为可深链详情，模态只保留短操作。
4. **P1 AI 准则**：建立来源/新鲜度/事实阶段组件，任何未来 AI 输出必须附证据和不确定性。
5. **P1 样式收敛**：消除历史主题级联，令所有颜色、边界、材料和 motion 从同一语义 token 输出。
