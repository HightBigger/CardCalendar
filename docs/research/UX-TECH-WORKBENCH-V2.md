## 1. 结论

当前正式界面已经有一部分 Apple 风格基础：系统中文字体、浅色语义 token、侧栏/顶栏的 `backdrop-filter`、焦点环和 `prefers-reduced-*` 退化。但它仍然是围绕年费 MVP 长出来的浅绿色后台，科技感目标尚未成为产品结构的一部分。

V2 将“科技感”定义为可核对的操作确定感：用户打开工作台后，能迅速知道下一步行动、规则来源和完成后留下的记录。深色石墨画布用于临期任务和高密度工作；浅色主题用于长文本、建档、打印和减弱透明度。半透明只承载结构层，不把活动、权益、积分批次做成玻璃卡片。

交付边界：本轮只交付视觉 token、信息层级、响应式原型和截图，不修改 `app/`、`components/`、接口或数据库。

## 2. 当前实际 UI 与目标的差距

| Before | After | Why |
| --- | --- | --- |
| `app/globals.css` 的主 token 仍沿用 `--green`、`--green-dark` 兼容别名，正式导航与内容视觉仍像年费工具 | 以 `--canvas`、`--surface`、`--surface-raised`、`--chrome` 和状态 token 建立 L0-L4 材质层；状态色只表达行动、风险和完成 | 科技感来自稳定的材料和语义层，而不是把品牌绿色换成霓虹色 |
| `components/mvp-app.tsx` 的一级视图是概览、我的卡片、年费日历、提醒中心、设置 | 工作台首屏统一展示卡片、活动、权益、刷卡任务、积分和提醒；刷卡任务是活动的可执行分段，不增加新的一级入口 | 后续工作台能力必须在同一优先级体系中被发现 |
| 指标区围绕卡片数、年费事件和待办，任务状态和来源不在同一行 | 待处理队列固定显示对象、状态轨道、截止日、当前/目标值、下一步、来源等级与最后核对日期 | 用户需要比较并行动，而不是只看数字墙 |
| 旧 `.status-pill` / `nav-count` 依赖颜色和圆角胶囊表达结果 | 逾期/临期/待核对使用 2-3px 状态轨道 + 中文状态文字 + 日期；标签只做来源等级 | 关闭颜色或在移动端没有 hover 时，状态仍然可理解 |
| 侧栏和顶栏有 Apple-style material，但内容面与悬浮层边界不清晰 | L3 透明 Chrome 只用于侧栏、顶栏、抽屉和 toast；任务、时间线、积分批次保持不透明实心数据面 | 透明表达空间关系，实心面保证中文和数字对比度 |
| `CardForm`、详情和删除审计主要通过模态承载 | 原型把右栏定位为短任务检查器；复杂建档、规则版本对比和审计进入完整详情页；移动端只改变容器为底部导航/抽屉 | 桌面与移动共享同一对象、URL、字段和状态，不复制业务逻辑 |
| 反馈以 toast 和固定时长过渡为主，业务异常尚未在工作台出现 | 动作原型统一表现按下、处理中、成功/失败、重试和撤销的位置；兑换“确认扣减”与“待入账”分开 | 金融记录必须可恢复，不能用一个“已保存”掩盖状态轴 |
| 只有“数据已同步/加载”式提示容易被看成实时系统 | 使用“最近核对 · 时间”与“官方已核验/待核对”来源协议；没有真实后台同步就不显示在线、扫描或 AI 预测 | 避免深色命令台过度承诺实时智能或银行资格判断 |

## 3. 视觉方向与 token

### 3.1 主题决策

- 默认按系统外观选择，允许用户记住手动选择；不根据临期程度自动切换主题。
- 深色主题是工作台的专注模式：石墨画布、蓝灰实心数据面、青蓝行动色、琥珀临期、珊瑚风险、绿色完成。
- 浅色主题是同一结构的阅读模式：不改变导航、间距、状态名或信息顺序，只替换画布、表面、边界和对比度。
- `prefers-reduced-transparency`、`prefers-contrast: more`、`forced-colors: active` 和 `prefers-reduced-motion` 必须保留结构和文字语义。

### 3.2 语义 token

| Token | Dark | Light | 使用边界 |
| --- | --- | --- | --- |
| `--canvas` | `#0b1118` | `#f4f6f8` | L0 页面画布；允许静止极弱网格，不使用大面积渐变 |
| `--surface` | `#111b25` | `#ffffff` | L1 任务、列表、表单、时间线和积分批次 |
| `--surface-raised` | `#172330` | `#f1f5f7` | L2 当前任务、摘要重点和详情检查器 |
| `--chrome` | `rgba(12,20,29,.82)` | `rgba(248,250,252,.84)` | L3 侧栏、顶栏、移动导航、toast；需要 blur fallback |
| `--text / secondary / tertiary` | `#edf5f8 / #a9bac5 / #718694` | `#16222b / #50616d / #74838d` | 正文、辅助、时间；不在半透明层使用过低对比灰 |
| `--accent` | `#54d6e8` | `#087f9d` | 主行动、链接、当前进度；不是银行品牌色 |
| `--success` | `#55d39a` | `#167548` | 已达标、已完成、可用 |
| `--warning` | `#f2bd68` | `#a35c00` | 临期、待核对、需要预约 |
| `--danger` | `#ff817c` | `#b83232` | 逾期、失败、争议 |
| `--info` | `#91b9ff` | `#3f6fae` | 一般信息、处理中和来源补充 |

基础间距使用 `4 / 8 / 12 / 16 / 20 / 24 / 32px`；数据面圆角 `6-8px`，浮层 `10-13px`；正文 `13-14px`、面板标题 `14-16px`、工作台标题 `27-34px`。金额、积分、日期、次数和百分比继承 `font-variant-numeric: tabular-nums`，中文正文 `letter-spacing: 0`。

### 3.3 材质规则

1. L0 画布：实色，静止极弱网格可帮助工作台定位，但不能呼吸或扫描。
2. L1 数据面：实色、单层边界、最多 8px 圆角；不依赖背景透出才能阅读。
3. L2 提升面：实色提高一层，配 2-3px 状态轨道或单条内亮边；不整块发光。
4. L3 Chrome：`backdrop-filter: blur(18-20px) saturate(130-150%)`、半透明背景和一条边界；不叠加第二层玻璃。
5. L4 重点：只给真正的行动/风险/焦点使用微弱光晕；禁止循环粒子、扫描线和动态背景。

## 4. 信息架构与关键状态

### 4.1 桌面 1440 × 900

```text
┌──────────── 244 sidebar ────────────┬──────────────────── topbar ────────────────────┐
│ Cardfolio                            │ 工作台 / 搜索 / 最近核对 / 主题 / 用户          │
│ 工作台  卡片  活动  权益  积分  提醒 │                                                │
│                                      ├──────────── content 1280 ──────────────────────┤
│                                      │ 问候 + 90天窗口 + 快速新增                        │
│                                      │ 待处理 / 进行中 / 权益 / 积分摘要                 │
│                                      │ ┌───────────────┬────────── 时间线 ─────────┐  │
│                                      │ │ 待处理队列     │ 未来30天                  │  │
│                                      │ │ 刷卡任务       │ 积分批次                  │  │
│                                      │ │                │ 对象焦点                  │  │
│                                      │ └───────────────┴──────────────────────────┘  │
└──────────────────────────────────────┴───────────────────────────────────────────────┘
```

首屏顺序固定为“待处理队列 → 刷卡任务 → 时间线/积分批次 → 对象摘要”。队列每项至少有对象类型、标题、状态文字、截止日/相对时间、当前/目标值、下一步、来源等级和最后核对日期。指标只做可下钻摘要，不应变成大号数字墙。

### 4.2 移动 390 × 844

- 顶栏 58px，侧栏变为从左进入的导航抽屉；关闭时恢复触发按钮焦点。
- 内容单列，待处理队列和刷卡任务保持相同字段；时间线按日期垂直排列。
- 底部导航只保留工作台、活动、权益、积分四个高频入口，卡片/提醒从对应列表或抽屉进入。
- 固定底部导航使用 `env(safe-area-inset-bottom)`；动作 toast 不遮挡导航和键盘安全区。
- 任何长标题、银行名和错误文案自然换行，不依赖 hover，不横向滚动。

### 4.3 状态轴

业务状态和可信度分开表达：

| 维度 | 示例 | 视觉表达 |
| --- | --- | --- |
| 生命周期 | 进行中、已完成、已归档 | 中文文字 + 中性边界 |
| 紧迫度 | 逾期、7 天内、30 天内 | 轨道颜色 + 截止日/剩余天数 |
| 来源可信度 | 官方已核验、官方信息不完整、用户自录待核对 | 小标签 + 最后核对日期 |
| 账本结果 | 待入账、已确认扣减、退款中、已退款 | 结果文字 + 时间线；不得提前改变余额 |

## 5. 动效与可访问性

实现阶段遵循 Apple Design 的响应、空间一致和可中断原则，以及 Emil Design Engineering 的高频动作减法原则：

| 场景 | 参数 | 约束 |
| --- | --- | --- |
| 按钮按下 | `scale(.98)`，`120-160ms ease-out` | 发生在 pointer-down；不改变列表布局 |
| 抽屉/侧栏 | `transform + opacity`，`220ms cubic-bezier(.32,.72,0,1)` | 从触发边进入，Escape、点击遮罩和再次打开都可中断 |
| Toast / popover | `scale(.98) + opacity + blur`，`160-200ms ease-out` | 从触发方向 materialize；不使用 `scale(0)` |
| 进度更新 | 轨道宽度一次过渡 `180ms` | 不循环发光；待入账和已确认必须有文本区分 |
| 键盘高频操作 | 无装饰动画 | 快捷键和连续录入不能被动效拖慢 |

`prefers-reduced-motion: reduce` 时取消位移和弹性，保留短暂颜色/透明度反馈；`prefers-reduced-transparency: reduce` 时 L3 变为实色；`prefers-contrast: more` 和 `forced-colors` 时提升边界并保留文字状态。按钮、导航和移动操作目标至少 44×44px，状态不能只依赖颜色。

## 7. 实施顺序与验收门

1. 建立共享 light/dark 语义 token，保留现有兼容变量但逐步将业务选择器迁移到语义类。
2. 先改造工作台壳层、待处理队列和任务进度；再将活动、权益、积分详情复用同一来源/新鲜度行。
3. 将复杂建档、规则版本和审计从长模态拆到深链页面；模态仅保留单一短任务。
4. 验证 1440×900、1280px、390×844 和 `prefers-*` 退化；确认无横向溢出、中文长文案不遮挡操作。
5. 接入真实接口前，补齐处理中、失败、重试、撤销和重复点击幂等测试。

通过条件：遮住标题后仍能通过状态文字和结构识别优先级；关闭颜色后仍能完成排序；减弱透明度后信息架构不变；移动端与桌面端使用同一对象状态和操作语义；兑换未到账和权益使用失败不会提前改写余额/额度。

### 设计决策

- 深色是工作台专注主题，浅色是同结构阅读主题；不把深色伪装成实时 AI 终端。
- 半透明仅用于结构性 Chrome，核心数据保持实心；科技感来自状态协议、来源新鲜度和稳定数字排版。
- 一级导航固定为工作台、卡片、活动、权益、积分、提醒；刷卡任务作为活动的执行视图。
- 风险、可信度和账本结果分轴表达；不能用一个颜色胶囊承载三种语义。
- 动效短、可中断、从触发源进入；键盘高频动作不播放装饰动画。

### 风险与后续验证

- 正式浅色 token 与本原型 token 尚未在真实 React 组件上统一，存在迁移时的视觉漂移风险。
- 深色中文正文、来源摘录和低对比辅助信息必须用浏览器实测 WCAG AA，不以截图或色值推断通过。
- 活动报名失败、权益使用失败、积分批次不一致、兑换退款和任务冲正仍需要真实交互走查。
- 移动底部导航是工作台原型的高频入口，正式产品需用实际信息架构验证“卡片/提醒”是否应保留在底部。
- `backdrop-filter` 在部分浏览器不可用时会退化为实色；需要验证焦点、阴影、边界和滚动层仍清晰。

## 9. 角色沟通记录

本稿由 UX / Design 角色整理，并向主会话 handoff。产品经理侧的活动、权益、刷卡任务、积分与兑换范围作为内容样本；架构/DBA 的状态轴和账本边界作为视觉状态命名依据；QA/安全的来源、所有权和异常恢复要求被保留在“来源新鲜度”和“可恢复反馈”中。视觉原型不替代这些正式契约。
