# 卡片档案（Cardfolio）产品需求文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 文档状态 | MVP 规划 |
| 产品形态 | 响应式 Web 应用 |
| 目标用户 | 个人信用卡持卡人 |

## 1. 背景与目标

### 1.1 背景

信用卡的年费周期、免年费规则和权益有效期分散在开卡材料、账单和银行 App 中。用户容易忘记扣费日，或者知道要刷卡免年费却无法快速判断当前进度。年费发生后，用户也缺少一个可以比较年费与权益收益的记录。

### 1.2 产品定位

卡片档案是一个个人信用卡信息管理工具，帮助用户记录每张卡的规则、跟踪免年费进度、在关键日期收到提醒，并在续卡前做出保留、降级或销卡决策。后续可自然扩展到账单、权益、积分与活动等卡片相关信息。

### 1.3 MVP 目标

1. 用户能在 3 分钟内完成首张卡的录入。
2. 用户能一眼看到未来 90 天的年费事件和每张卡的免年费进度。
3. 用户能手动更新刷卡次数或消费金额，系统自动计算完成度和剩余量。
4. 用户能在年费发生前收到站内提醒，避免因遗忘产生不必要的费用。
5. 所有数据由用户主动录入，不要求提供完整卡号或银行登录凭据。

### 1.4 MVP 衡量指标

- 首次登录后完成首张卡创建的比例不低于 70%。
- 已创建卡片中，设置至少一个提醒的比例不低于 60%。
- 关键页面（首页、卡片详情）在常规网络下 2 秒内可交互。
- 每个年费周期至少有一次用户确认或更新记录（用于验证核心工作流）。

## 2. 用户画像

### 2.1 主要用户：多卡个人用户

- 持有 3--15 张信用卡，来自不同银行。
- 关心免年费刷卡次数、消费金额和年费扣收日期。
- 愿意每月或每季度手动更新一次数据，希望减少记忆负担。

### 2.2 次要用户：轻度持卡用户

- 持有 1--3 张卡，偶尔忘记年费日。
- 更需要简单的日期提醒，不需要复杂的权益分析。

### 2.3 不在 MVP 范围内的用户

- 企业或家庭共享账户用户。
- 需要自动读取银行账单、短信或网银的重度用户。
- 需要投资级收益分析或金融建议的用户。

## 3. 核心使用场景

1. **新卡录入**：用户拿到新卡，填写银行、卡名、尾号、年费和免年费规则，保存后即能看到下一次年费日。
2. **周期跟踪**：用户每次刷卡后，或每月汇总后，更新次数和消费金额，查看距离免年费目标还差多少。
3. **年费提醒**：系统在用户设置的日期（默认提前 30 天、7 天、1 天）显示待办提醒；用户处理后可标记已确认。
4. **扣费确认**：年费发生后，用户记录实际扣费、减免或退费状态，形成可追溯的年度记录。
5. **续卡决策**：用户查看该卡的年费、已记录权益价值和使用情况，记录“保留/降级/销卡/待决定”。

## 4. MVP 范围

### 4.1 包含

- 基础账号登录、退出和个人时区设置。
- 信用卡新增、编辑、查看、归档（不直接删除历史记录）。
- 年费规则和免年费目标配置。
- 免年费进度手动更新及历史记录。
- 年费周期记录：待确认、已免除、已扣费、已退费、无需处理。
- 首页概览、未来 90 天年费日历/列表和提醒中心。
- 站内提醒、提醒完成/忽略、提醒设置。
- 卡片搜索、按银行/状态/年费时间筛选和排序。
- 数据导出（JSON，CSV 导出/导入列入 P1）和账户数据删除。

### 4.2 不包含

- 读取或代管完整卡号、CVV、密码、银行登录凭据。
- 直接连接银行 API、自动同步交易或自动扣费。
- 短信、邮件、微信/钉钉推送（可作为后续版本能力）。
- 多人共享、家庭账户、企业报销和自动账单 OCR。
- 基于金融数据的投资、授信或保证收益建议。

## 5. 功能需求

优先级定义：P0 为 MVP 必须，P1 为首个可用版本后补充，P2 为远期探索。

### 5.1 账号与个人设置（P0）

- 邮箱和密码注册、登录、退出；密码必须经过安全哈希存储。
- 首次登录设置时区，默认使用浏览器时区；日期展示和提醒计算使用该时区。
- 用户可以导出自己的全部数据并申请删除账户及数据。

### 5.2 信用卡管理（P0）

卡片字段：

- 发卡银行（可输入，也可从常用银行列表选择）。
- 卡片名称/级别。
- 卡号后四位（必填，限制为 4 位数字）。
- 卡片状态：使用中、已停用、已归档。
- 年费金额及币种（默认人民币，可填 0）。
- 年费周期：按开卡日、固定日期或自定义日期；下一次年费日。
- 免年费规则：无条件、刷卡次数、消费金额、次数与金额同时满足、自定义说明。
- 目标次数、目标金额、统计周期起止日。
- 备注和创建/更新时间。

行为要求：

- 新增和编辑均需校验必填项，尾号、金额、日期格式合法。
- 归档卡片后不再产生新提醒，但历史年费和进度仍可查看。
- 删除操作默认只允许归档；账户删除前需二次确认。

### 5.3 免年费进度（P0）

- 以次数和/或金额展示当前值、目标值、剩余值和完成百分比。
- 用户可录入一次“本周期累计值”，也可追加一条手动变更记录。
- 每条记录包括日期、次数增量、金额增量、备注；支持编辑和撤销最近一次错误记录。
- 达到规则目标后显示“已达标”，并停止该周期的进度提醒。
- 周期结束后自动生成新周期，上一周期记录只读保留。
- 不同条件之间明确显示“同时满足”或“满足其一”，避免误解。

### 5.4 年费周期与处理记录（P0）

- 系统根据年费日生成当前及未来 12 个月的年费事件。
- 用户可将事件标记为：待确认、已免除、已扣费、已退费、无需处理。
- 已扣费/已退费状态可填写实际金额、发生日期和备注。
- 事件详情显示关联卡片、规则、提醒历史和处理状态。

### 5.5 首页概览（P0）

- 显示卡片总数、使用中卡片数、未来 90 天待处理年费数。
- 显示需要关注的免年费进度（剩余量最多的若干张）和最近提醒。
- 显示按日期排序的近期年费列表，点击可进入卡片详情或事件处理页。
- 空状态提供“新增第一张卡”主操作。

### 5.6 年费日历与提醒（P0）

- 日历支持月视图和列表视图；事件按卡片和状态区分颜色/标签。
- 默认提醒提前 30 天、7 天和 1 天，用户可以关闭某个节点或自定义提前天数。
- 提醒在到期日当天仍未处理时，首页显示逾期提示。
- 用户可将提醒标记为完成或稍后处理；操作需记录时间。
- MVP 只保证站内提醒，提醒发送失败不影响年费事件数据。

### 5.7 搜索与筛选（P0）

- 支持按银行、卡片名称、尾号后四位搜索。
- 支持按卡片状态、年费状态、年费日期范围、免年费是否达标筛选。
- 列表支持按年费日、剩余进度、创建时间排序。

### 5.8 权益与收益记录（P1）

- 用户可为卡片添加权益项目：名称、有效期、使用次数/额度、估算价值、已使用价值和备注。
- 年度汇总展示年费、权益估算价值和用户手动记录的净收益。
- 系统只做记录和算术汇总，不给出金融承诺或自动化投资建议。

### 5.9 CSV 导入导出（P1）

- 导出全部卡片、周期、进度和提醒数据为 CSV；JSON 导出属于 MVP 能力。
- 支持按模板导入 CSV；导入前提供预览、字段校验和错误行下载。

## 6. 关键流程

### 6.1 首次使用

注册/登录 -> 设置时区 -> 新增卡片 -> 填写年费与免年费规则 -> 选择提醒节点 -> 保存 -> 进入卡片详情。

### 6.2 更新免年费进度

首页待办或卡片详情 -> 选择当前周期 -> 输入累计次数/金额或追加记录 -> 系统校验并计算剩余量 -> 保存 -> 达标则更新状态并关闭进度提醒。

### 6.3 处理年费事件

收到站内提醒 -> 打开年费事件 -> 核对规则和进度 -> 选择已免除/已扣费/已退费/无需处理 -> 填写实际信息（可选） -> 标记完成。

### 6.4 归档卡片

卡片详情 -> 选择归档 -> 二次确认 -> 停止未来提醒、保留历史数据 -> 可在“已归档”筛选中恢复为使用中。

## 8. 非功能需求

### 8.1 安全与隐私

- 只存储卡号后四位，禁止在表单、日志和分析事件中收集完整卡号、CVV、密码或银行凭据。
- 全站 HTTPS；密码使用成熟的慢哈希算法；会话具备过期、退出和基础防暴力破解能力。
- 用户只能访问自己的卡片、事件和提醒数据；服务端必须执行所有权校验。
- 重要操作（归档、删除账户、导出数据）需要二次确认并记录审计时间。

### 8.2 性能与可用性

- 首页和卡片详情在典型网络下首屏可交互时间不超过 2 秒，常规接口 p95 响应不超过 500 ms。
- 单用户至少支持 100 张卡片、每张卡片 10 年历史记录，不因数据量增长明显卡顿。
- 关键数据写入具备事务一致性；服务异常时不重复生成年费事件或提醒。

### 8.3 兼容性与可访问性

- 支持最近两个版本的 Chrome、Edge、Safari 和 Firefox，适配 360 px 以上移动端宽度。
- 颜色不作为唯一状态表达方式；表单、键盘操作和错误提示可被屏幕阅读器识别。

### 8.4 可维护性

- 年费日期、周期切换和提醒计算使用统一的时区和日期库，避免夏令时/跨日错误。
- 核心计算（进度、剩余量、事件生成）需有单元测试；关键流程需有端到端测试。
- 提供基础错误监控、结构化日志和数据备份策略。

## 9. MVP 验收标准

1. 新用户可以注册、登录并创建一张卡片；刷新页面后数据仍存在。
2. 卡片详情能正确展示年费金额、下一次年费日、免年费规则及进度。
3. 输入次数/金额时，系统正确计算完成百分比和剩余量；非法或负数输入会被阻止并提示原因。
4. 系统能生成未来 12 个月的年费事件；归档卡片不会生成新的事件或提醒。
5. 提前 30/7/1 天的站内提醒按用户时区出现；标记完成后不再出现在未处理列表。
6. 年费事件的五种处理状态（含“待确认”及四种处理结果）可保存、修改并在详情中显示历史。
7. 首页、卡片列表、日历、提醒中心之间可通过导航和详情链接互相到达，移动端无横向溢出。
8. 服务端拒绝访问其他用户的卡片 ID；日志和数据库中不存在完整卡号或密码明文。
9. 用户可以导出自己的 JSON 数据并删除账户；两项操作都有明确的二次确认。CSV 导入/导出属于 P1，不作为 MVP 验收条件。
10. 核心单元测试覆盖日期、周期、进度和提醒计算；主流程端到端测试通过。

## 10. 后续迭代

### V1.1：提高录入和提醒效率

- 常用银行/卡种规则模板，可一键复制卡片。
- 邮件和浏览器 Push 提醒；可配置免打扰时间。
- CSV 导入、导出和批量编辑。
- 权益记录和年度收益看板。

### V1.2：减少手动维护

- 账单 PDF/短信的本地解析预览，用户确认后写入进度。
- 可选的第三方账单同步（单独授权、可随时撤销）。
- 规则变更提醒和历史版本。

### V2：决策与多端

- 基于用户实际年费和权益记录的续卡建议，并展示计算依据。
- PWA 离线查看与移动端快捷录入。
- 家庭共享空间、权限和审计（需重新评估隐私模型）。

## 11. 产品边界与风险

- 年费和免年费规则可能因银行、卡种、活动和客户资质变化；产品展示“用户录入的信息”，不保证规则准确，详情页应提供“最后核对日期”。
- 提醒是辅助工具，不替代银行官方通知；所有提醒文案应避免承诺免年费或收益。
- 任何自动同步能力上线前必须完成用户授权、撤销、数据最小化和异常处理设计。
