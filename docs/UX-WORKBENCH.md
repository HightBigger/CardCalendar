# Cardfolio 工作台 UX 与信息架构规范

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 工作台扩展设计建议 |
| 文档版本 | v0.5（第五轮信息架构复核） |
| 基线 | `main@e756538` |
| 目标终端 | 响应式 Web，支持 360 px 及以上宽度 |
| 设计目标 | 中文、Apple 风格、密集但可扫描、可渐进扩展 |

## 1. 设计目标与边界

Cardfolio 从“信用卡年费管理”扩展为“个人信用卡管理工作台”。界面应让用户先处理时间敏感事项，再查卡片资产，最后进入活动、权益与积分的专项管理，而不是把每个新增领域都变成一个醒目的独立入口。

本规范遵循以下原则：

1. **卡片是聚合核心**：活动、权益、刷卡任务、积分账户和兑换记录都必须能回到关联卡片；跨卡比较则进入各专项列表。
2. **工作台是行动入口**：工作台回答“现在最该处理什么”，不复制所有模块的数据仓库。
3. **列表用于扫描，详情用于判断**：列表只放识别、紧迫度、进度和下一步动作；完整规则、来源、历史与备注进入详情。
4. **事实与推测分开**：规则型信息必须展示来源、有效期和最后核对时间；系统不得把用户录入、第三方信息或过期规则写成银行承诺。
5. **常用路径在前，配置下一层**：首屏只保留高频动作和异常；模板、历史版本、高级筛选、批量配置进入二级界面。
6. **熟悉、克制、可恢复**：延续现有系统字体、低装饰密度、8 px 以内卡片圆角和明确分隔；重要写操作提供即时反馈与撤销，只有不可轻易恢复的操作才二次确认。
7. **扩展不等于加菜单**：新增能力优先成为现有对象的标签页、筛选维度、关联面板或工作台卡片，满足一级导航准入条件后才独立。

“Apple 风格”在此指清晰层级、即时反馈、空间一致、克制材料、自然且可中断的动效，以及完整的辅助功能适配；不复制任何公开产品的品牌视觉。可借鉴的通用模式包括任务收件箱、主从列表、详情检查器和移动端底部抽屉。

## 2. 信息架构

### 2.1 六个稳定一级入口

桌面侧栏按语义分为三组，但不增加可折叠的多级菜单：

| 分组 | 一级入口 | 回答的问题 | 不放什么 |
| --- | --- | --- | --- |
| 今日管理 | **工作台** | 现在要处理什么？整体状态如何？ | 完整历史、所有低优先级对象 |
| 今日管理 | **卡片** | 我有哪些卡？某张卡的完整情况是什么？ | 跨卡活动发现、跨卡兑换比较 |
| 价值管理 | **活动** | 哪些活动值得关注？参与任务完成到哪？ | 卡片基础信息、独立积分流水 |
| 价值管理 | **权益** | 还有哪些可用权益？何时失效？ | 营销活动规则、兑换订单 |
| 价值管理 | **积分** | 各积分账户有多少、何时过期、兑换进展如何？ | 信用额度、金融收益建议 |
| 辅助 | **提醒** | 有哪些已触发、稍后处理或已完成的提醒？ | 设置入口、所有普通对象列表 |

“设置”继续固定在账户区，不占用业务一级入口；全局搜索、快速新增和通知状态位于顶栏。

**刷卡任务不设一级菜单。** 它是活动规则的可执行实例，也可能是独立的免年费任务，因此通过以下位置进入：

- “活动”页的二级分段控件：`全部活动 / 刷卡任务`；
- 工作台的“待处理”统一队列；
- 卡片详情的“活动与任务”标签页；
- 全局搜索结果的“任务”分类。

这样既能让任务成为高频工作流，又不会形成“活动”和“任务”两个含义重叠的一级入口。

### 2.2 一级导航准入规则

未来模块只有同时满足以下条件才可申请一级入口：

- 用户至少每月主动访问，而不是只被提醒带入；
- 拥有独立的跨卡列表和详情，不只是某张卡的属性；
- 有至少两种持续性工作流，无法被现有“活动、权益、积分”之一清晰容纳；
- 与已有入口名称不会造成对象归属歧义；
- 在 360 px 移动导航中仍能保持不超过 7 个业务入口。

不满足时按顺序采用：详情标签页 → 模块内分段控件 → 筛选视图 → 工作台可选模块。一级导航不使用无限嵌套或每个银行一项的树形菜单。

## 3. 全局框架与工作台

### 3.1 桌面框架

- 左侧为固定侧栏，保留品牌、六个业务入口、待处理计数和底部账户区。
- 顶栏依次显示移动菜单（适用时）、面包屑、全局搜索、快速新增、提醒入口和账户动作。
- “快速新增”是一个菜单，而不是多个并排主按钮：`卡片 / 活动 / 权益 / 刷卡任务 / 积分余额 / 兑换记录`；根据当前页面预选最相关类型。
- 内容区建议最大宽度 1280 px；列表页面可使用全宽表格，详情正文保持适合阅读的行宽。
- 页面标题区只保留标题、结果摘要和一个主操作。说明性副标题仅在首次使用或复杂状态下出现，日常页面不反复解释功能。

### 3.2 工作台首屏

工作台不是指标墙。首屏按“风险 → 行动 → 概况”排序：

1. **状态摘要条**：未来 7 天待处理数、未来 30 天到期价值、未来 90 天年费金额。每项都可进入带预设筛选的列表。
2. **待处理队列**：首屏主区域，最多展示 6 项，按逾期、7 天内、规则存疑、价值到期、普通待办排序。
3. **近期时间线**：显示未来 30 天的年费、任务截止、权益到期和积分到期；同日事件合并，避免重复卡片。
4. **数据可信度提示**：仅当存在超过核对期限、规则变化或来源存疑时出现；不以长期空占位卡片存在。

每条待办必须在一行内回答：

- 发生什么：如“白金卡年度权益将在 7 天后到期”；
- 属于谁：银行、卡名与尾号；
- 何时截止：绝对日期加相对时间；
- 当前差距：还差次数、金额、名额或待确认步骤；
- 下一步：一个主动作，如“更新进度”“记录使用”“核对规则”。

首屏以下再展示：

- 卡片健康概览：使用中、停用、归档及缺失信息；
- 进行中的刷卡任务；
- 即将到期权益与积分；
- 最近更新与已完成事项；
- 用户选择显示或隐藏的低优先级摘要模块。

### 3.3 工作台优先级

默认排序从高到低：

1. 已逾期且尚未处理；
2. 7 天内到期且仍有差距；
3. 规则已变化、来源不可信或关键字段缺失；
4. 30 天内权益或积分到期；
5. 90 天内年费事件；
6. 普通维护和建议核对。

同一对象的多条提醒聚合成一项，展开后查看触发记录。用户完成、忽略或稍后处理后，该项立即离开当前队列，并提供短时“撤销”。工作台不能自动把“看过”当成“已处理”。

## 4. 卡片列表与详情层级

### 4.1 卡片列表

默认使用紧凑行列表；当屏幕足够宽时允许用户切换到卡面网格，但网格不是默认，因为多卡比较更依赖列对齐。

列表首屏字段：

| 字段 | 展示规则 |
| --- | --- |
| 卡片识别 | 银行、卡名、尾号；不显示完整卡号 |
| 状态 | 使用中 / 已停用 / 已归档，文字与图形共同表达 |
| 下一关键日期 | 取最近的年费、任务或权益截止日，并标明事件类型 |
| 免年费进度 | 百分比加“还差 X 次 / ¥X”，明确“同时满足”条件 |
| 年费 | 金额、币种与下一年费日 |
| 数据新鲜度 | 仅在待核对、已过期或来源存疑时显示状态 |
| 行动作 | 打开详情；更多菜单放编辑、复制、归档等低频动作 |

完整备注、所有活动、权益明细、积分流水、规则原文和历史不进入列表行。

### 4.2 卡片详情的信息层级

卡片详情使用完整页面，顶部保持可见的对象身份和上下文。

**详情首屏必须展示：**

- 银行、卡名、尾号、卡片状态；
- 下一年费日、年费金额及当前处理状态；
- 当前免年费规则、逻辑关系、进度和剩余量；
- 最近一个跨模块截止事项；
- 规则来源、最后核对时间和可信状态；
- 主动作“更新进度”，以及次动作“记录事项”；
- 面包屑或明确返回“卡片”的路径。

**详情首屏不展示：**

- 超过 3 条的历史记录；
- 所有周期完整表单；
- 来源正文全文、长备注和附件；
- 已结束活动、已用尽权益和旧兑换的全部明细；
- 归档、导出等低频管理动作。

详情标签页职责如下：

| 标签页 | 首段内容 | 深层内容 |
| --- | --- | --- |
| 概览 | 最近截止、免年费进度、可用权益、积分余额、异常 | 各模块最多 3 条摘要与“查看全部” |
| 年费与免年费 | 当前周期、规则、剩余量、快捷更新 | 历史周期、年费事件、提醒记录、处理历史 |
| 活动与任务 | 进行中和即将开始 | 已结束、未参加、完整任务记录 |
| 权益 | 可用、已预约、即将到期 | 已使用、已用尽、已过期 |
| 积分 | 余额、最近到期批次、兑换处理中 | 余额历史、调整记录、兑换历史 |
| 记录 | 最近人工变更 | 全量审计时间线、备注和来源版本 |

标签切换不丢失滚动前的对象上下文。通过工作台待办进入详情时，应直接定位到对应标签和记录，并高亮一次，不让用户再次寻找。

### 4.3 详情操作

- 顶部主动作随上下文变化：未达标为“更新进度”，临近年费为“处理年费”，规则异常为“核对规则”。同一时刻只显示一个主动作。
- 编辑基础资料、设置提醒、复制卡片、归档放入“更多”菜单。
- 快捷编辑使用右侧检查器（桌面）或底部抽屉（移动）；跨多个区块的复杂编辑进入独立页面。
- 归档后保留历史，顶部显示只读横幅；“恢复使用”是明确动作，不在浏览历史时自动恢复提醒。

## 5. 活动、任务、权益与积分

### 5.1 活动列表与详情

“活动”表示有明确参与时间、规则、条件和奖励的营销或用卡计划；“权益”表示持卡资格带来的可使用项目。二者不得只因都能产生价值而混用。

活动页默认显示“我关注的活动”，可切换“全部活动 / 刷卡任务”。列表支持紧凑表格和按截止日分组的时间线视图。

**活动列表首屏字段：**

- 活动名称、关联银行和卡片；
- 状态：未开始 / 进行中 / 待确认 / 已完成 / 已过期 / 已取消；
- 活动周期及距离截止时间；
- 奖励摘要及用户记录的估算价值，明确标注“估算”；
- 参与五轴摘要：资格 / 报名 / 名额 / 任务进度 / 奖励；`submitted`、`target_reached` 和“待发”均显示为待核对，不合并成“已完成”；
- 规则可信状态和最后核对时间；
- 下一步动作：关注、报名已确认、创建任务或查看结果。

**活动详情层级：**

1. 标题区：活动名称、状态、时间、关联卡片、关注与提醒动作；
2. 结论摘要：资格、当前进度、奖励、下一步和截止日；
3. 规则条件：渠道、地区、支付方式、商户范围、名额、上限、排除项；
4. 关联刷卡任务：每个目标的逻辑关系和进度；
5. 来源与核对：来源类型、链接或附件、获取时间、最后核对、历史版本；
6. 记录：报名、进度变更、奖励到账与用户备注。

无法确定资格时写“资格待确认”，不能显示“可参加”。奖励未到账时写“已完成，待确认奖励”，不提前计入已获得价值。

### 5.2 刷卡任务列表与详情

任务既可来自活动，也可独立服务于免年费。任务类型至少支持次数、累计金额、指定渠道、指定商户、连续周期和自定义条件；复合条件必须显示“同时满足”或“满足其一”。

**任务列表首屏字段：**

- 任务名称与来源（活动 / 免年费 / 自定义）；
- 关联卡片；
- 状态：未开始 / 进行中 / 已达标 / 待确认 / 未达标 / 已取消；
- 截止日期和剩余天数；
- 当前值、目标值、剩余值及进度；
- 最近更新时间；
- 快捷动作“更新进度”。

**任务详情：**

- 顶部只显示目标、差距、截止日、关联卡片和主动作；
- “规则”区展示计入范围、不计入范围、统计周期和条件逻辑；
- “进度”区支持追加增量与设置累计值，并明确两种模式；
- “记录”区展示日期、增量、来源、备注、修正或撤销关系；
- “结果”区区分系统计算的“已达标”和用户/银行确认的“奖励已到账”或“年费已免除”。

系统可根据人工记录计算进度，但不能自动把计算达标等同于银行最终认定。

### 5.3 权益列表与详情

权益列表默认按“需要使用”排序：即将到期、已预约待使用、可用、已用尽、已过期。

**权益列表首屏字段：**

- 权益名称、类别和关联卡片；
- 当前状态：待下发 / 可用 / 下发失败 / 暂停 / 已撤销 / 已过期；额度投影另显示可用 / 部分使用 / 已用尽；
- 总次数或额度、已用、剩余；
- 有效期或下次重置日；
- 使用限制摘要；
- 估算价值与已记录价值，二者分列；
- 来源可信状态；
- 快捷动作“记录使用”或“标记预约”。

**权益详情：**

1. 剩余量、有效期、重置规则和主动作；
2. 使用方法：渠道、入口、预约要求、地区、同行人等；
3. 价值记录：单次估算、实际记录、累计值，不生成收益承诺；
4. 来源、最后核对和规则版本；
5. 使用记录、取消/回退记录与备注。

无次数上限的权益显示“次数不限”，不用 `∞` 单独表达。仅有资格但尚未核实可用性时显示“待核对”，不计入“可用权益”总数。

### 5.4 积分账户、到期批次与兑换

“积分”一级页使用三个分段：`账户 / 到期批次 / 兑换记录`。余额属于卡片或银行积分计划，但同一银行多张卡可能共用账户，界面不可默认一张卡等于一个积分账户。

**积分账户列表首屏字段：**

- 积分计划或账户名称、关联卡片；
- 当前余额和余额日期；
- 最近到期批次：数量、日期、剩余天数；
- 估算价值区间，仅在用户提供换算依据时显示；
- 最近核对时间和来源可信状态；
- 快捷动作“更新余额”或“记录兑换”。

**积分账户详情：**

- 首屏：余额、最近到期、关联卡片、最后核对、主要动作；
- 首屏同时显示确认余额、账面余额、批次合计、`reconciliation_difference` 与 `unallocated_difference`；任一差额不为零或未知时显示“待核对”，不显示合并的可用余额；
- 到期批次：按先到期排序，允许余额与批次合计不一致并明确提示；
- 余额记录：新增、消费、调整、过期和人工更正；
- 兑换入口：只记录计划和结果，不代替用户完成外部兑换；
- 来源与备注：银行账单、银行 App、人工记录等。

**兑换列表首屏字段：**

- 兑换项目、积分计划、关联卡片或账户；
- 消耗积分与现金附加金额；
- 用户记录的估算价值；
- 状态：计划中 / 已提交 / 处理中 / 成功 / 已取消 / 失败 / 退款处理中 / 已退款；积分扣减状态独立显示为未扣、处理中、已入账、待核对或已退回；
- 提交日、预计或实际到账日；
- 下一步动作，如“确认到账”。

**兑换详情：** 展示兑换内容、数量、消耗、价值依据、处理时间线、凭证/备注、关联积分扣减和来源。价值换算必须显示计算依据，不用单一“最优兑换”结论替代用户判断。

## 6. 首次使用与日常维护

### 6.1 首次使用

首次使用采用渐进式引导，不要求一次录完所有扩展模块：

1. **账户准备**：登录后确认时区；说明日期和提醒会使用该时区。
2. **录入首张卡**：第一步只要求银行、卡名、尾号、卡片状态；禁止完整卡号和 CVV。
3. **设置核心规则**：填写下一年费日、年费金额、免年费规则与统计周期。条件选择后只显示相关字段。
4. **设置提醒**：预选 30 / 7 / 1 天，可跳过并沿用默认设置。
5. **核对摘要**：保存前用一句自然语言复述规则，例如“2027 年 5 月 20 日前消费 6 次且满 ¥20,000”。
6. **进入卡片详情**：显示已建立的年费任务；提供三个非阻塞后续动作“添加权益”“添加活动”“记录积分余额”。

首张卡成功保存即完成核心引导。后续字段以工作台的“完善资料”低优先级任务提示，不能用连续模态框阻塞用户。

空账户的工作台仅显示一个主操作“新增第一张卡”，附带“从模板开始”和“导入数据”（能力可用时）两个次入口。不要同时展示六个空模块。

### 6.2 日常维护

建议的每周或每月维护流程：

1. 从工作台查看逾期和 7 天内事项；
2. 就地完成轻量动作：更新任务进度、记录权益使用、确认兑换到账；
3. 进入对象详情核对复杂规则或修正记录；
4. 处理完当前队列后查看 30 天时间线；
5. 对超过核对期限的数据逐项“确认仍有效”或“更新规则”；
6. 系统保留最近变更，并允许撤销可恢复操作。

快速更新成功后，界面必须同时反馈新值、目标差距和状态变化。例如：“已记录 2 次；当前 5/6 次，还差 1 次。”仅显示“保存成功”不足以支持核对。

## 7. 状态体系与异常处理

### 7.1 状态表达规则

- 状态由文字、图标/形状和色彩共同表达；不能只有颜色点。
- 同一对象只显示一个生命周期主状态，可信度和时间紧迫度作为独立辅助状态，不混成“黄色进行中”等含糊标签。
- 标签文字使用完整中文；列表允许短标签，详情需给出原因和时间。
- 红色只用于错误、逾期和高风险变化；橙色用于即将到期或待确认；绿色用于已完成或已达标；蓝色用于当前选择和一般信息。
- “已达标”只描述计算条件，“已确认”描述用户或外部结果，二者不可互换。

### 7.2 通用页面状态

| 状态 | 表现 | 必须提供的动作 |
| --- | --- | --- |
| 首次空状态 | 对象图标、原因、一个主操作；文案针对当前模块 | 新增首个对象；必要时返回卡片 |
| 筛选无结果 | 保留筛选条，说明没有匹配项，显示生效筛选 | 清除筛选；不得误导用户新增重复数据 |
| 已全部处理 | 简短完成状态和下一时间点 | 查看已完成或返回工作台 |
| 首次加载 | 保持页面骨架与稳定尺寸，避免布局跳动 | 超过合理时间后显示加载说明 |
| 局部加载 | 只替换对应列表/面板，不遮住整页 | 保持其他可用内容可操作 |
| 整页错误 | 说明未加载的范围，保留已缓存且标明时间的数据 | 重试、返回上一级 |
| 局部错误 | 在失败模块内显示，不用单一 toast 取代 | 重试该模块 |
| 保存错误 | 表单值不丢失，字段错误就近显示 | 修正并重试；未知错误可再次保存 |
| 无权限/已删除 | 说明对象不可用，不泄露对象详情 | 返回所属列表 |
| 离线或网络中断 | 显示当前数据时间；未确认写入不得表现为成功 | 重试；支持时保留草稿 |

空状态文案示例：

- 首次空：“还没有权益。为一张卡添加权益，开始记录剩余次数和有效期。”
- 筛选空：“没有符合‘30 天内到期 + 可用’的权益。”动作：“清除筛选”。
- 完成态：“本周没有待处理事项。下一项是 8 月 28 日的年费核对。”

### 7.3 过期状态

- 对象过期后默认移至“已过期”，不从历史中消失。
- 过期详情顶部显示过期日期和最终记录；所有规则和进度默认只读。
- 如需延长有效期，应创建新周期或新版本，不直接覆盖旧周期。
- 过期对象仍可补记结果，但必须标明“补记”和实际记录时间。
- 工作台在过期后只保留需要确认结果的事项；已确认的过期对象不持续制造提醒。

### 7.4 规则变更

规则变更必须作为可审阅事件处理：

1. 对象列表显示“规则有更新”，详情顶部出现非阻塞警示横幅；
2. 详情提供旧版与新版的字段级对比：时间、门槛、渠道、奖励、上限和排除项；
3. 明确展示变更来源、发现时间、最后核对时间及受影响的任务；
4. 用户确认后选择“采用新规则”或“保留当前记录”；
5. 采用新规则时先预览进度和提醒如何变化，不静默重算已完成周期；
6. 所有旧版本可追溯，撤销只创建新修订，不删除历史。

若规则变化会让原本“已达标”变成“未达标”，状态先变为“待确认”，不可直接降级并发送确定性警告。

### 7.5 来源不可信或信息陈旧

规则型对象统一显示以下可信状态：

| 状态 | 含义 | 界面处理 |
| --- | --- | --- |
| 已核对 | 用户在有效核对周期内确认，且有明确来源 | 普通显示，详情可查来源与时间 |
| 待核对 | 新录入、缺少关键字段或从未确认 | 列表显示中性标签，工作台可生成维护项 |
| 可能已变化 | 超过建议核对期限或跨越新周期 | 显示警示和“核对规则”，不自动判错 |
| 来源存疑 | 来源无法访问、相互冲突或为非官方转述 | 降低视觉确定性，禁止使用“确定可得”等文案 |

来源详情至少包括：来源类型（银行官方 / 用户材料 / 用户录入 / 第三方）、标题或说明、链接/附件、获取时间、适用地区/渠道、最后核对人和时间。

“银行官方”只描述来源类型，不代表内容永远有效；仍需显示获取和核对日期。列表不堆叠完整来源，只在异常时显示可信标签。

## 8. 搜索、筛选、排序与批量操作

### 8.1 全局搜索

顶栏搜索覆盖卡片、活动、任务、权益、积分账户和兑换记录。结果按对象类型分组，每项显示对象名、关联卡片、匹配字段和状态；尾号仅支持后四位。搜索结果可直接打开可深链详情。

默认不搜索长备注全文，除非用户选择“搜索备注”，避免敏感文本在快速结果中意外暴露。无结果时提供拼写提示和“在当前模块中清除筛选”。

### 8.2 模块筛选

所有列表遵守相同结构：搜索框 → 常用筛选 → 排序 → “更多筛选” → 已应用条件摘要。筛选状态写入 URL，返回列表时保留；用户可保存个人视图，但默认视图名称使用具体结果，如“30 天内到期”，不用“我的视图 1”。

| 模块 | 常用筛选 | 默认排序 |
| --- | --- | --- |
| 卡片 | 状态、银行、年费日期、免年费达标、可信状态 | 最近关键日期 |
| 活动 | 状态、关联卡片、截止范围、参与状态、奖励类型、可信状态 | 截止时间 |
| 任务 | 状态、来源、关联卡片、截止范围、任务类型 | 紧迫度，其次剩余差距 |
| 权益 | 可用状态、类别、关联卡片、到期范围、剩余量 | 到期时间 |
| 积分账户 | 积分计划、关联卡片、到期范围、可信状态 | 最近到期时间 |
| 兑换 | 状态、积分计划、提交/到账日期、价值类型 | 最近更新 |
| 提醒 | 待处理/稍后/已完成、类型、日期范围 | 触发时间 |

已应用筛选以可移除条件显示，并始终提供“清除全部”。结果计数紧邻页面标题，不使用只靠颜色变化的筛选激活态。

### 8.3 批量选择与操作

- 默认不显示整排复选框；用户点击“选择”或勾选首项后进入批量模式。
- 批量工具条固定显示已选数量、当前页/全部结果范围、可用操作和退出。
- “全选”先选择当前已加载结果；选择跨页全部结果需要明确的第二步，例如“选择全部 126 项”。
- 筛选变化前若已有选择，应询问清除选择还是保留匹配项，不能静默扩大范围。
- 完成后显示结果摘要：成功数、失败数及失败原因；部分失败可只重试失败项。

推荐批量操作范围：

| 对象 | 允许 | 不允许直接批量执行 |
| --- | --- | --- |
| 卡片 | 设置提醒、添加标签、归档、恢复 | 修改尾号、覆盖年费规则、删除历史 |
| 活动 | 关注/取消关注、设置提醒、归档 | 批量宣称已报名或奖励到账 |
| 任务 | 设置提醒、归档、自定义任务可批量标记取消 | 批量修改规则、批量认定达标 |
| 权益 | 设置提醒、归档、标记待核对 | 批量记为已使用或修改剩余量 |
| 积分账户 | 设置核对提醒、标记待核对 | 批量覆盖余额 |
| 兑换记录 | 导出、归档已结束记录 | 批量确认到账或重写消耗积分 |
| 提醒 | 完成、稍后处理、忽略 | 跨对象修改原始规则 |

归档等可恢复操作完成后提供短时撤销；影响提醒或多个对象的操作先显示影响摘要。账户删除等不可逆操作仍需二次确认，并要求用户明确理解范围。

## 9. 移动端抽屉与响应式

### 9.1 响应式布局

| 宽度 | 导航 | 内容策略 | 详情策略 |
| --- | --- | --- | --- |
| ≥ 1180 px | 固定侧栏 | 工作台双列；列表使用对齐列 | 完整详情页，可辅以右侧轻量检查器 |
| 768–1179 px | 可收起侧栏或导航抽屉 | 工作台单列；次要列移至主内容下方 | 完整详情页，标签可横向滚动 |
| 360–767 px | 顶栏菜单 + 左侧导航抽屉 | 单列；摘要横向滚动或 2 列，不缩小正文 | 完整页面；轻量编辑使用底部抽屉 |

列表在移动端转为语义行，不把桌面表格按比例压缩：首行对象名与状态，第二行最近日期与进度，第三行只在异常时显示来源或错误。低优先级列进入详情或行菜单。所有固定区域考虑安全区，不产生横向溢出。

### 9.2 导航抽屉

- 从左侧菜单按钮打开，与其空间来源一致；关闭沿相同路径返回。
- 抽屉包含六个一级入口、提醒计数和账户区；当前页使用 `aria-current="page"`。
- 打开后焦点进入当前导航项，Tab 被限制在抽屉内；Escape、关闭按钮和点击遮罩均可关闭，随后焦点回到菜单按钮。
- 内容滚动被锁定，抽屉自身可滚动；不因设备横竖屏变化丢失当前页面。
- 动效须可中断，拖拽时内容与手指 1:1 跟随，释放时根据速度和位置决定关闭或回弹；不在过渡中锁住输入。

### 9.3 底部抽屉

以下轻量任务使用底部抽屉：筛选、排序、更新一次任务进度、记录一次权益使用、更新积分余额、确认兑换到账。新增卡片、复杂规则编辑和规则版本对比使用完整页面。

- 抽屉标题明确对象和动作，如“更新白金卡任务进度”；不使用泛称“编辑”。
- 有清晰拖拽把手、关闭按钮和固定底部主操作；键盘弹出时主操作不得被遮挡。
- 中间状态随手势连续变化，可在关闭动画中重新抓取；边界使用渐进阻力。
- 默认使用无明显弹跳的快速弹簧；只有用户甩动抽屉时允许轻微动量反馈。
- 关闭未保存表单时保留草稿并提示，只有确认丢弃才清空。
- `prefers-reduced-motion: reduce` 时取消位移和弹性，改用短暂淡入淡出；`prefers-reduced-transparency: reduce` 时使用实色表面。

移动端不使用侧滑手势承载唯一的完成、删除或归档操作，防止与系统返回手势冲突。

## 10. 可访问性

目标为 WCAG 2.2 AA，并覆盖中文屏幕阅读器和键盘用户的核心路径。

### 10.1 结构与键盘

- 页面只有一个 `h1`，标题层级连续；使用 `nav`、`main`、`section`、`table/list` 等语义结构。
- 所有功能可用键盘完成；可见焦点不被 sticky 顶栏或底栏遮挡。
- 图标按钮必须有可访问名称和悬停提示；同一图标在全局保持同一含义。
- 分段控件按 tabs 模式实现，支持方向键、Home/End 和正确的 `aria-selected`、`aria-controls`。
- 模态框、导航抽屉和底部抽屉打开时管理焦点，关闭后回到触发元素；背景不可被辅助技术继续浏览。
- 表格的列头、排序状态、选择范围和批量结果可被读出；移动卡片行保持等价阅读顺序。

### 10.2 状态、图形与反馈

- 状态、进度和紧迫度不能只依赖颜色。进度条提供可读名称、当前值、目标值和剩余值。
- 正文、次要文字、边框及交互状态满足相应对比度；高对比模式下使用实色表面和明确边框。
- 触控目标至少 44 × 44 px；相邻危险和普通操作留足间距。
- 保存成功用 `role="status"` 的非打断播报；错误用 `role="alert"`，同时将焦点移到错误摘要或首个无效字段。
- 骨架屏对辅助技术隐藏，另提供“正在加载卡片列表”等状态文本；加载完成后不抢走用户焦点。
- toast 只补充即时反馈，不能作为错误说明或唯一的撤销入口；需要后续处理的信息保留在页面内。

### 10.3 表单与输入

- 每个输入有持久可见标签；占位符只给格式示例，不代替标签。
- 金额同时标明币种，日期使用用户时区；错误说明包含原因与修正方式。
- 复合规则使用可读句子预览，并为“同时满足 / 满足其一”提供显式控件。
- 自动补全、日期控件和数字步进不阻止用户手动输入；输入过程中不因格式化移动光标。
- 保存按钮禁用时仍需说明原因；异步保存防止重复提交但不冻结其他页面操作。

### 10.4 动效、字体与材料

- 动效首先服务于空间关系和反馈，不用循环动画装饰工作台。
- 支持减弱动效、减弱透明度和增强对比；这些偏好不影响信息完整性。
- 使用系统字体与动态字号；不随视口宽度缩放字体，字间距保持 0；放大至 200% 时不遮挡或截断关键内容。
- 半透明只用于浮动导航、工具栏或抽屉等层级表面，正文列表保持实色；不可在半透明层上继续叠加半透明卡片。

## 11. 中文文案规范

### 11.1 术语

| 使用 | 定义 | 避免 |
| --- | --- | --- |
| 工作台 | 跨模块的当前行动与摘要 | 首页、总览、Dashboard 混用 |
| 卡片 | 信用卡档案对象 | 账户（积分账户除外） |
| 活动 | 有参与周期、条件和奖励的计划 | 权益活动混称 |
| 权益 | 因持卡资格可使用的项目 | 优惠、福利随意替换 |
| 刷卡任务 | 有目标、进度和截止日的执行项 | 挑战、打卡 |
| 积分账户 | 余额与到期批次的归属单位 | 默认等同某张卡 |
| 兑换记录 | 用户计划或已发起的兑换 | 自动兑换 |
| 已达标 | 系统按现有记录计算满足条件 | 已确认、保证成功 |
| 待核对 | 信息尚未被用户确认 | 错误、无效 |

### 11.2 写法

- 使用直接动词命名操作：“新增卡片”“更新进度”“记录使用”“确认到账”“核对规则”。避免“确定”“提交”等脱离对象的泛称。
- 状态描述“发生了什么”，错误描述“为什么”和“怎么继续”。例如：“余额已记录，但低于本地流水：差额待核对。请检查本次调整。”真实负余额可以保留，但必须标记 `needs_review`，不能用 0 覆盖差异。
- 日期在紧迫场景写绝对日期加相对时间：`2026 年 8 月 19 日（7 天后）`；历史只写绝对日期和时间。
- 金额包含币种或符号，积分使用千位分隔；估算价值始终带“估算”，不要与已记录价值相加后写成“收益”。
- 条件完整表达逻辑：“消费 6 次且累计满 ¥20,000”，不要写“6 次 / ¥20,000”。
- 来源提示保持中性：“此规则由你在 2026 年 8 月 12 日录入，尚未核对银行来源。”
- 风险文案不制造确定性：“规则可能已变化，请在银行官方渠道核对”，避免“规则已失效”，除非有已确认的新版本。
- 提醒是辅助：“建议在年费日前核对”，避免“保证免年费”“不会扣费”。
- 空状态不使用责备语气，不反复说明产品功能；一段原因配一个明确动作即可。
- 按钮不使用省略号表示还有下一级；通过菜单图标、箭头和上下文表达。

## 12. 分阶段落地建议

### 阶段 1：稳固框架

- 将“概览”重命名为“工作台”，建立六入口分组，但尚未上线的模块可不显示空壳入口。
- 将卡片详情改为可深链完整页面，保留现有年费、进度、提醒和历史能力。
- 统一状态标签、来源字段、最后核对时间和工作台待办模型。
- 保留现有紧凑视觉语言和移动导航抽屉行为。

### 阶段 2：加入活动、任务与权益

- 上线活动列表/详情和内嵌“刷卡任务”分段；工作台接入跨模块待办。
- 上线权益剩余量、有效期和使用记录。
- 建立规则版本对比、过期和来源存疑状态。

### 阶段 3：加入积分与效率能力

- 上线积分账户、到期批次和兑换记录。
- 增加保存视图、批量操作和工作台模块偏好。
- 数据量与使用频率达到准入标准后，再评估未来模块是否需要一级入口。

阶段切换时不可预先展示不可用的导航空壳。新模块上线前，相关摘要和快速新增项也不应出现。

## 13. 设计验收清单

### 信息架构

- 六个一级入口含义互斥且可说明对象归属；刷卡任务不形成重复入口。
- 任一跨模块对象都能回到关联卡片，任一卡片都能进入其活动、权益和积分记录。
- 新功能经过一级导航准入规则，不因模块数量增长导致菜单无限扩张。

### 核心流程

- 新用户可在 3 分钟内保存首张卡，不被活动、权益和积分录入阻塞。
- 用户从工作台待办到对应详情和操作不超过 2 次导航动作。
- 更新任务、权益或积分后能看到新值、差距、状态和最近记录。
- 归档、撤销、规则变更和过期记录均可追溯。

### 状态与可信度

- 首次空、筛选空、完成、加载、局部错误、保存错误、过期、规则变化和来源存疑均有独立设计。
- 所有规则型对象都能显示来源、适用范围、有效期和最后核对时间。
- 系统计算达标、用户确认和银行最终结果在文案与状态上明确区分。

### 响应式与辅助功能

- 360 px 无横向溢出；列表不压缩成不可读表格；固定操作不被软键盘或安全区遮挡。
- 抽屉、标签、表单和批量模式可完整键盘操作，并正确恢复焦点。
- 200% 文字缩放、减弱动效、减弱透明度和增强对比下信息与操作仍完整。
- 状态不用颜色单独表达，触控目标至少 44 × 44 px，错误可被屏幕阅读器识别。

## 14. 风险与待验证项

1. **一级入口仍可能过多**：六个入口已接近个人工具的上限。应通过可用性测试确认“活动”和“权益”能否被用户稳定区分；若混淆持续，应先合并为“价值”页面的分段，而非增加解释文字。
2. **统一待办可能过载**：年费、任务、权益和积分紧迫度不同。需用真实多卡数据验证排序，并允许用户隐藏低价值类型，避免所有事项都被标成紧急。
3. **来源状态增加维护成本**：最后核对时间能提升可信度，也会增加录入负担。默认核对周期和提醒频率需要按对象类型研究，不宜用一个全局天数。
4. **卡片详情标签过多**：六个标签在移动端需要横向滚动。应验证用户能否发现后部标签，并考虑在“概览”中提供稳定的模块跳转。
5. **价值汇总易被误解**：活动奖励、权益估值和兑换价值不能简单合并成“收益”。任何汇总都必须区分估算、已记录和未到账。
6. **批量操作风险**：批量改规则或余额会破坏审计与可信度，因此本规范刻意限制批量写入；若未来放开，需先设计预览、逐项校验和可回滚记录。
7. **动效实现风险**：抽屉的速度继承、可中断性和焦点管理需要真实设备验证；仅靠静态视觉验收不足。

建议使用 3–15 张卡、跨 3 家银行、同时存在规则变化和临期权益的真实规模数据做桌面与 360 px 移动端原型测试，重点观察：用户是否先处理真正紧迫事项、是否能区分活动与权益、能否理解“已达标但待确认”，以及能否在 30 秒内找到某张卡的下一关键日期和来源。

## 15. 第二轮复核与交互修订

本轮以 `docs/PRD.md`、`docs/PRD-WORKBENCH.md` 与本规范前述章节交叉复核，重点验证卡活动、卡权益、刷卡任务、积分与兑换能否在桌面和移动端形成同一条可追溯闭环。以下条目是对前述规范的补充；如有歧义，以本节的流程和状态约束为准。

### 15.1 复核结论与术语修订

第一轮的信息架构覆盖了四类对象，但需要补齐三项契约：

1. **导航短标签与领域术语分层**：一级导航继续使用易扫描的短标签“活动”“权益”“积分”；页面 `h1`、新增菜单、全局搜索分类和表单标题使用完整名称“卡活动”“卡权益”“积分与兑换”。“刷卡任务”始终使用完整名称，不缩写为“任务”，除非已处于“刷卡任务”页面内部。
2. **任务入口与 PRD 对齐**：PRD 信息架构中的“任务中心”在 UX 上实现为“活动”下的固定二级视图“刷卡任务”，不新增一级入口。工作台待办、卡片详情和可深链 URL 均可直接进入该视图，因此功能可达性不降低。
3. **状态轴相互独立**：每个对象同时保留生命周期、用户处理状态、规则可信度和时间紧迫度四个维度。列表主标签只显示生命周期；“待核对”“来源存疑”作为可信度标签，“7 天后到期”“已逾期”作为时间信息，不再用一个含糊状态覆盖全部含义。

PRD 的可信度与 UX 展示文字按下表映射，数据值不因展示简化而丢失：

| PRD 来源等级或状态 | 列表短标签 | 详情说明 |
| --- | --- | --- |
| 官方已核验 | 已核对 | 官方来源、访问日期、用户核对日期和适用范围 |
| 官方页面但信息不完整 | 待核对 | 已找到官方页面，但资格、渠道或数值仍不完整 |
| 第三方公开资料 | 来源存疑 | 第三方资料仅供记录，需到银行官方渠道核对 |
| 用户自录待核对 | 待核对 | 用户录入时间、缺失字段和建议核对动作 |
| 规则已超过有效期或被替代 | 可能已变化 | 旧版生效区间、新版来源及受影响对象 |

“未知”是字段值，不是错误状态。未知有效期不得生成虚假到期提醒；未知资格不得显示“可参加”“可用”或“可兑换”。

### 15.2 四条端到端核心流程

所有端在领域步骤、校验、保存结果和历史记录上保持一致，只改变容器：桌面使用列表与右侧检查器并置，移动使用完整详情页与底部抽屉。用户从工作台待办进入时，系统带入对象、关联卡片和触发原因，不要求重复选择。

#### 卡活动：录入、报名、执行、核对奖励

```text
活动列表 / 卡片详情
-> 新增卡活动
-> 录入时间窗、适用卡、资格、报名、渠道、地区、奖励与来源
-> 保存为“待核对”或“进行中”
-> 用户在银行官方渠道报名
-> 记录“报名成功 / 报名失败 / 尚未确认”
-> 创建或关联刷卡任务
-> 更新任务进度
-> 系统显示“已达标，待确认奖励”
-> 用户记录奖励到账、未到账或申诉中
-> 活动结束后只读保留规则版本与处理时间线
```

- 桌面端新增使用独立页面或宽表单；活动详情右侧检查器只承载关注、报名结果、提醒和奖励结果等单一动作。
- 移动端新增与复杂规则编辑使用完整页面；“记录报名结果”“更新进度”“确认奖励”使用底部抽屉。
- 报名失败必须记录失败日期与原因，并保留“重新报名”或“标记不再参加”；不能自动取消关联任务。
- 活动结束时若奖励未确认，主状态为“已结束”，用户处理状态为“奖励待确认”，工作台继续显示一条结果核对事项。

#### 卡权益：建档、预约、使用、结算剩余量

```text
卡片详情 / 权益列表
-> 新增卡权益
-> 录入周期、次数或额度、激活/预约要求、渠道、地区、来源
-> 核对后进入“可用”；未核对则保持“待核对”
-> 需要预约时记录预约结果
-> 使用前展示将扣减的数量与当前剩余
-> 记录实际使用
-> 更新剩余量和实际价值
-> 取消或未使用时创建回退记录
-> 周期结束后冻结旧周期，并可创建新周期
```

- 权益“预约成功”不等于“已使用”；列表分别显示预约状态与剩余量。
- 记录使用前必须预览：关联卡片、权益周期、使用日期、本次用量、保存后剩余量。跨周期或用量超过剩余时阻止保存，并解释修正方式。
- 取消预约不改变用量；已记录使用被取消或退回时新增回退记录，不删除原使用记录。
- 无限次权益仍记录使用历史，但不显示伪造的百分比进度。

#### 刷卡任务：建立口径、更新进度、处理冲正、核对结果

```text
活动详情 / 年费与免年费 / 刷卡任务列表
-> 创建或关联刷卡任务
-> 选择次数、金额、复合或自定义目标
-> 明确统计周期、渠道、地区、排除项和退款口径
-> 预览自然语言规则
-> 追加增量或设置累计值
-> 系统计算当前值、目标值与剩余量
-> 退款/冲正时新增负向修正并说明来源
-> 达标后进入“已达标，待确认”
-> 用户核对奖励、年费或银行认定结果
```

- “追加增量”和“设置累计值”必须是互斥分段，切换时保留草稿但不混算。
- 负数不作为普通进度输入开放；退款、冲正和撤销通过明确的“记录退款/冲正”流程写入，避免误操作。
- 规则不完整时仍可保存草稿，但不能给出确定的达标结论；进度区域显示“按当前已录入规则估算”。
- 规则版本变化只影响用户确认迁移的新任务；进行中和已完成任务保持原规则引用。

#### 积分与兑换：核对余额、维护批次、记录外部兑换、确认结果

```text
积分与兑换 -> 积分账户
-> 新增账户并选择积分单位
-> 记录余额日期和来源
-> 录入已知到期批次；未知有效期保持未知
-> 到期提醒进入工作台
-> 用户在银行官方渠道发起兑换
-> Cardfolio 记录计划或订单状态
-> 预览所需积分、现金补差、资格与预计影响批次
-> 标记“已提交 / 处理中”但暂不扣减已确认余额
-> 用户确认成功后生成扣减流水并关联批次
-> 失败、取消或退款保留订单；只有确认官方已退回积分后才生成关联 reversal
```

- 创建兑换记录不等于代用户兑换；主按钮使用“记录兑换”，不能使用“立即兑换”。
- “计划中”不占用余额；“已提交/处理中”可显示“预计占用”，但不能混入已确认余额。只有“已到账/成功”才生成确认扣减。
- 兑换成功前展示影响预览：积分账户、单位、所需积分、现金补差、预计扣减批次、关联卡权益（如有）和保存后的余额。外部成功但本地余额不足时保留真实负余额并标记待核对，不静默归零。
- 账户余额与到期批次合计不一致时同时展示两者，标记“需要核对”，不自动填充未知批次。
- 退款不删除成功兑换；先进入“退款待核对”，只有官方确认积分退回后才生成关联 reversal 并进入“已退款”。恢复积分的新有效期未知时明确标记未知。

### 15.3 桌面与移动交互一致性

| 场景 | 桌面 | 移动 | 一致性要求 |
| --- | --- | --- | --- |
| 浏览与比较 | 对齐列列表；详情打开完整页面 | 语义行列表；详情打开完整页面 | 相同默认排序、筛选和字段优先级 |
| 快速记录 | 右侧检查器，不遮住对象摘要 | 底部抽屉，固定主操作并避开软键盘 | 相同字段、默认值、校验和成功反馈 |
| 复杂建档/规则编辑 | 完整页面，可双列布局 | 完整页面，单列分步展开 | 保存草稿、来源与规则预览一致 |
| 规则对比 | 双栏字段级对比 | 单列“旧值 / 新值”逐字段对比 | 同一变化摘要与采用规则 |
| 筛选 | 行内常用筛选 + 更多筛选面板 | 筛选底部抽屉，顶部显示结果预估 | 应用前不改变结果；URL 状态相同 |
| 失败与重试 | 失败区块内重试，检查器保留输入 | 抽屉不自动关闭，字段和滚动位置保留 | 不重复写入；成功后播报相同结果 |

右侧检查器和底部抽屉都只处理一个明确意图。涉及两个以上关联对象、规则版本迁移、批量影响或不可逆结果时，统一升级为完整页面，不因桌面空间较大而把复杂流程塞入检查器。

移动端详情标签修订为“概览页模块跳转 + 可滚动标签”双路径：概览首屏提供“年费与任务、卡活动、卡权益、积分与兑换”四个有计数的文本入口；标签滚动到屏幕外时保留边缘截断提示。不能让横向滑动成为发现后部模块的唯一方法。

### 15.4 分模块状态修订

| 对象 | 空状态 | 错误状态 | 待核对 | 已过期 / 已结束 |
| --- | --- | --- | --- | --- |
| 卡活动 | “还没有卡活动”；主操作“新增卡活动”，次操作“从卡片添加” | 报名、进度、奖励分别局部报错；保留已成功步骤 | 说明缺少资格、渠道、时间或来源中的哪些字段 | 规则只读；奖励未确认则保留结果待办，已确认则移入历史 |
| 卡权益 | “还没有卡权益”；从关联卡预填卡片 | 预约失败不扣次数；使用保存失败不改变剩余量 | 不计入可用数，不显示可预约；提供“核对权益” | 旧周期只读；允许补记使用并标注补记时间；续期创建新周期 |
| 刷卡任务 | 活动无任务时提供“创建刷卡任务”；无目标时不显示 0% | 进度保存失败保留模式与输入；重复提交不新增两条记录 | 规则摘要标“按当前记录估算”，不自动认定达标 | 冻结目标与最终进度；未核对结果可继续处理，不能继续追加普通进度 |
| 积分账户 | “还没有积分账户”；先选积分计划和单位 | 更新余额失败保留余额日期与来源；批次错误不覆盖账户余额 | 余额、有效期、批次可分别待核对 | 过期批次保留；未知有效期不进入过期列表 |
| 兑换记录 | “还没有兑换记录”；主操作“记录兑换” | 提交/处理失败保留订单和失败原因；不得先扣余额 | 资格、库存、比例或到账结果未知时分别提示 | 失效计划不可继续提交；成功、失败、取消、退款均保留完整时间线 |

状态操作的共同修订：

- **局部原子性**：一次动作涉及对象状态和数值变化时，要么全部成功，要么界面保持原状态；不得出现“兑换失败但余额已扣”或“权益使用失败但次数已减”。
- **重试幂等**：重试按钮沿用原操作标识。界面可显示“正在确认上次保存结果”，但不能鼓励连续点击。
- **草稿可恢复**：网络错误、误关抽屉或页面返回时保留本地草稿；草稿不计入正式进度、余额或提醒。
- **来源错误不阻断浏览**：来源链接失效时保留已保存的标题、摘录和访问日期，并把可信度转为“来源存疑”；不隐藏整个对象。
- **过期不等于完成**：对象越过截止日先进入“已过期/已结束”，若结果尚未核对则仍保留一个明确待办。

页面与控件使用下列固定名称：

| 位置 | 使用名称 | 说明 |
| --- | --- | --- |
| 一级导航 | 工作台 / 卡片 / 活动 / 权益 / 积分 / 提醒 | 为扫描效率使用短标签 |
| 页面标题 | 卡活动 / 卡权益 / 积分与兑换 | 第一次出现时给出完整领域名称 |
| 活动二级视图 | 我关注的 / 全部卡活动 / 刷卡任务 | “我关注的”只筛活动，不包含权益 |

“报名状态”“任务进度”“奖励结果”在活动详情中分开；“预约状态”“使用状态”“剩余量”在权益详情中分开；“订单状态”“到账状态”“余额影响”在兑换详情中分开。中文界面不得用一个“状态”字段承载这些不同问题。

状态文案进一步统一：

- 活动生命周期：`未开始 / 进行中 / 已结束 / 已取消`；规则不可靠另标 `待核对`。

- 任务结果：`未开始 / 进行中 / 已达标 / 未达标 / 已取消`，达标后可附 `结果待确认`。
- 权益使用：`可用 / 部分使用 / 已用尽 / 已过期 / 暂不可用 / 尚未确认`。
- 兑换订单：`计划中 / 已提交 / 处理中 / 已到账 / 失败 / 已取消 / 已退款 / 尚未确认`。

内部英文状态不得直接出现在用户界面。中文标签与数据状态建立单一映射，并在列表、详情、筛选、提醒和导出说明中复用。

### 15.6 可访问性复核修订

- 桌面右侧检查器使用有名称的互补区域；如果阻断背景操作则按模态对话框管理焦点，否则不设置焦点陷阱。移动底部抽屉承载表单时按模态对话框处理，背景设为不可交互。
- 抽屉拖拽把手不是唯一关闭方式；始终提供“关闭”按钮。手势未达到阈值时回到原位，不触发保存或丢弃。
- 活动、任务、权益和兑换时间线使用有序列表；每条记录的可访问名称包含日期、动作、数值变化、执行者来源和结果。
- 任务复合条件不能只画流程线。屏幕阅读器文本完整读作“需同时满足：消费 6 次；累计金额满 20,000 元”。“满足其一”同理。
- 积分余额与到期批次使用真实文本和表格表头；图表为补充，提供相同数据的列表或摘要。
- 状态标签的可访问名称包含维度，如“活动状态：进行中”“规则可信度：待核对”，避免连续读出多个无上下文的状态词。
- 快捷保存后的 `role="status"` 播报必须包含对象和结果，例如“白金卡机场权益已记录使用 1 次，剩余 2 次”；不能只播报“成功”。
- 写入失败时焦点移到抽屉或检查器内的错误摘要，摘要链接到具体字段；重试后焦点留在原任务上下文，不跳回页面顶部。
- 相对日期的可访问名称同时包含绝对日期，例如视觉显示“7 天后”，读作“2026 年 8 月 19 日，7 天后”。
- 横向滚动标签支持键盘方向键并保持选中项可见；移动概览的四个模块入口提供不依赖横向手势的替代导航。
- 200% 文字缩放时检查器改为覆盖式单列或完整页面，固定按钮不得遮住最后一个字段；400% 重排下核心浏览与单项记录仍可完成。
- 超时、库存、资格与余额等会变化的信息在用户提交前再次以文本确认；更新不能只用颜色闪烁，且不会在用户阅读时自动移走焦点。

## 16. 第二轮真实边界复核（补充）

本节以基线 `e756538` 的 `docs/PRD-WORKBENCH.md`、本文件前述信息架构和现有视觉方向为准，将“线索、未知、失败、处理中、争议和历史修正”转成用户可理解的界面状态。它不改变卡片为核心聚合、手动优先和不自动操作银行的产品边界。

### 16.1 MVP 与未来工作台共存

MVP 年费功能和未来工作台不是两套产品：MVP 视图是稳定的事实来源，工作台是跨对象的行动入口。

| 层级 | MVP 现有入口 | 未来扩展入口 | 共存规则 |
| --- | --- | --- | --- |
| 工作台 | 概览中的年费事件、免年费进度、提醒 | 活动线索、权益到期、积分批次、兑换结果 | 首屏优先显示年费/逾期/7 天内事项；未来事项按相同时间与可信度排序，不能覆盖年费事实 |
| 卡片 | 我的卡片、卡片详情、年费周期 | 卡活动、卡权益、积分与兑换标签 | 卡片详情仍是对象归属和历史入口；扩展数据为空时显示添加动作，不显示空壳指标 |
| 年费日历 | 月视图、列表视图 | 同一时间线可显示活动、权益、积分到期 | 年费事件保留现有状态和处理入口；其他事件标明对象类型，点击深链到各自详情 |
| 提醒 | 待处理、稍后、完成、忽略 | 活动报名/奖励、权益预约/使用、积分到期、兑换结果 | 统一提醒队列，但提醒必须显示触发原因和原对象状态；完成提醒不等于完成业务结果 |
| 设置 | 默认年费提醒、账户和时区 | 对象核对周期、显示主题、免打扰 | 新设置采用增量字段；未支持的能力不在设置中展示不可用开关 |

落地要求：

- 旧路由和旧中文标签保留可达性；“概览”可以在视觉上改名“工作台”，但刷新、返回和深链不能丢失年费上下文。
- 新模块采用渐进显示：没有活动、权益、积分或兑换数据时，不在侧栏显示空的未来入口；工作台只显示一个“添加”或“完善资料”动作。
- 当前 MVP 的卡片详情、年费事件和提醒可直接打开；未来对象从工作台进入时，带入对象 ID、关联卡、触发原因和目标标签页。
- 所有扩展对象都能回到卡片详情；卡片详情的历史记录是审计事实，不因工作台筛选而隐藏。
- “AI”只描述可解释的排序、聚合和来源提示；不能出现“智能认定资格”“自动判断可用”“自动优化兑换”等文案或按钮。

### 16.2 工作台与详情的信息架构修订

#### 桌面工作台

桌面首屏固定为三层：

1. **行动摘要**：逾期、未来 7 天、待核对和处理中数量。每个数字是链接，可进入带筛选的列表。
2. **待处理队列**：最多 6 项，显示对象类型、银行/卡片、触发原因、绝对日期与相对时间、状态和主操作。每项只保留一个主操作，次操作进入更多菜单。
3. **时间线与对象摘要**：左侧显示年费/活动/任务，右侧显示权益/积分/兑换；同日事件合并，但每个对象仍有独立深链。

如果用户只有 MVP 数据，工作台仍保持同样三层，但只显示年费和免年费事项；不使用“暂无活动/权益/积分”四个空卡填满首屏。

#### 卡片详情

卡片详情首屏保持以下顺序：

1. 卡片身份：银行、卡名、尾号、卡片生命周期和最后核对日期；
2. 当前关键事实：下一年费日、免年费规则、当前确认进度和剩余量；
3. 跨模块焦点：最近一个活动/任务/权益/积分或兑换异常；
4. 来源和可信度：来源等级、适用范围、规则版本和“待核对”原因；
5. 主操作：根据当前异常只显示一个，例如“更新进度”“核对资格”“记录使用”“核对余额”。

标签顺序固定为：`概览 / 年费与任务 / 卡活动 / 卡权益 / 积分与兑换 / 记录`。未来新模块先落入“概览”摘要或“记录”，不直接新增标签。已归档卡片和已过期规则进入只读状态，仍可从历史时间线查看。

#### 活动与刷卡任务

“卡活动”列表和“刷卡任务”列表使用同一页的分段控件，但两者不是同一对象：活动负责线索、资格、报名和奖励；任务负责口径、目标、进度和证据。详情页通过关联区互相跳转。

列表行固定显示：对象名称、关联卡片、截止日、生命周期、可信度、当前差距和主操作。不要在列表使用“参加”“立即达标”等承诺式动作。

#### 积分与兑换

“积分与兑换”页面分为 `积分账户 / 到期批次 / 兑换记录` 三个分段。积分账户是余额事实，批次是到期事实，兑换记录是外部动作结果；三者不合并成一张“积分余额卡”。

兑换详情必须同时显示：积分账户与单位、所需积分、现金补差、资格/库存来源、订单状态、积分处理状态和预计影响批次。P1-b 只记录用户在外部银行渠道完成的动作，不提供“兑换”或“提交到银行”按钮。

#### 提醒中心

提醒中心按 `待处理 / 稍后处理 / 已完成 / 已忽略` 分段。每条提醒显示：触发对象、触发原因、对象当前状态、触发日期、截止日期和主操作。

“完成提醒”只改变提醒状态，不自动把活动标为已报名、把权益标为已使用、把任务标为已达标或把兑换标为已到账。提醒中心必须提供“打开原对象”作为次操作。

### 16.3 真实边界的状态与操作规范

以下状态是业务事实的可读投影。生命周期、用户处理、可信度和时间紧迫度保持独立，避免一个标签承担多个问题。

#### 卡活动

| 状态 | 用户看到什么 | 主操作 | 次操作 | 禁止暗示 |
| --- | --- | --- | --- | --- |
| 活动线索 | `活动线索 · 待官方核对`；显示来源类型、发现日期和缺失字段 | `核对资格` | 查看来源、保存到关注 | 不显示“可参加”“已符合” |
| 资格未知 | `资格待确认`；列出卡种、地区、渠道或客群中未知的字段 | `补充资格记录` | 查看规则版本、标记稍后核对 | 不自动创建“可达标”任务 |
| 尚未报名 | `尚未报名`；显示报名截止日和是否必须报名 | `记录报名结果` | 查看报名渠道、设置提醒 | 不提供“立即报名” |
| 报名失败 | `报名失败`；显示失败日期和用户输入的原因 | `记录重新尝试` | 查看失败记录、取消关注 | 不自动取消活动或任务 |
| 奖励待发 | `已达标 · 奖励待发`；显示预计发放日和核对依据 | `核对奖励结果` | 查看任务进度、记录争议 | 不显示“已获得价值” |
| 奖励已撤回/争议 | `奖励已撤回` 或 `奖励有争议`；保留原达标快照 | `记录争议` | 查看规则版本、查看历史 | 不把原活动历史改写成未参加 |

活动线索和资格未知可以进入工作台，但默认优先级低于真正截止且已确认的任务；只有存在明确日期或用户设定提醒时才进入时间线。

#### 卡权益

| 状态 | 用户看到什么 | 主操作 | 次操作 | 数值规则 |
| --- | --- | --- | --- | --- |
| 待下发 | `权益待下发`；显示预计下发日、服务商和缺失凭证 | `核对下发` | 查看来源、记录服务商 | 不计入“可用权益” |
| 可用 | `可用`；显示剩余次数/额度、有效期、预约要求和适用范围 | 无预约则 `记录使用`；需预约则 `预约记录` | 查看限制、设置提醒 | 仅用户确认后才减少剩余量 |
| 已预约 | `已预约 · 待使用`；显示预约时间、地点/服务商和取消规则 | `记录使用` | `记录取消预约` | 预约不减少使用量 |
| 已使用 | `已使用`；显示日期、用量、实际费用和记录来源 | `查看使用记录` | 记录修正 | 原记录只读，修正以反向记录完成 |
| 现场拒绝 | `现场未使用 · 服务商拒绝`；显示拒绝原因和时间 | `记录拒绝原因` | `核对权益`、记录争议 | 不减少次数/额度，不记入已使用价值 |
| 暂停/争议 | `暂不可用` 或 `使用有争议`；显示影响范围和来源 | `核对权益状态` | 查看历史、稍后处理 | 不自动重算旧周期 |

“预约成功”不能用绿色“已完成”表达；它是预约状态，不是使用结果。现场拒绝、容量限制和额外收费都保留原尝试，并要求用户确认是否产生实际扣减。

#### 刷卡任务

| 状态 | 用户看到什么 | 主操作 | 次操作 | 进度口径 |
| --- | --- | --- | --- | --- |
| 进行中 | `进行中`；显示已确认值/目标值/剩余值 | `更新进度` | 查看规则、添加记录 | 只计入当前规则允许的已记录值 |
| 暂时达标 | `暂时达标 · 待入账/待核对`；显示满足的是哪些条件 | `核对任务结果` | 查看证据、查看入账延迟 | 不关闭提醒，不写成银行已确认 |
| 待入账 | `待入账`；单独列出 pending 次数/金额及预计入账日 | `更新入账结果` | 查看规则、稍后处理 | pending 不计入 confirmed 进度 |
| 退款重开 | `退款后重新核对`；显示原达标快照、退款流水和新差距 | `处理退款/冲正` | 查看原记录、查看规则版本 | 新增负向流水，重算当前值，不删除原记录 |
| 有争议 | `进度有争议`；显示争议字段、证据和最后核对日 | `记录争议` | 查看流水、核对官方规则 | 暂停“已达标”结论，保留历史快照 |
| 已达标/已核对 | `已达标 · 已核对` | `查看记录` | 记录修正 | 规则版本和核对时间固定显示 |

普通进度输入不开放负数；退款、冲正、撤销必须从明确的修正入口产生反向记录。任务从暂时达标变为有争议时，工作台显示状态变化原因，不用红色闪烁代替说明。

#### 积分账户与批次

| 状态 | 用户看到什么 | 主操作 | 次操作 | 计算规则 |
| --- | --- | --- | --- | --- |
| 余额已核对 | `余额已核对`；余额日期、来源和单位可见 | `查看流水` | 更新余额、添加批次 | 余额是用户确认的账本值，不称为实时余额 |
| 余额与批次不一致 | `需要核对 · 差额 ¥/分`；同时显示账户总额、批次合计和未分配差额 | `核对余额` | `记录未分配差额`、查看流水 | 不自动把差额分配到任何到期批次 |
| 到期未知 | `到期未知`；明确没有可验证日期 | `补充到期信息` | 查看来源、设置核对提醒 | 不生成虚假到期日或“临期”提醒 |
| 批次临期 | `即将到期`；显示批次数量、单位和绝对日期 | `核对批次` | 查看兑换记录、设置提醒 | 只针对有明确 expires_on 或来源规则的批次 |
| 批次已过期 | `已过期`；保留过期流水和来源 | `记录过期结果` | 查看历史、记录调整 | 不删除余额或隐藏批次 |

积分账户列表使用账户主行、批次次行。差额用文本和 2 px 轨道表达，不能用大面积红色面把正常的人工对账差异误报为系统错误。

#### 兑换记录

| 状态 | 用户看到什么 | 主操作 | 次操作 | 积分处理 |
| --- | --- | --- | --- | --- |
| 计划中 | `计划中`；显示项目、所需积分和现金补差 | `编辑计划` | 删除草稿、查看来源 | 不占用、不扣减 |
| 处理中 | `处理中 · 等待外部结果`；显示提交日、预计结果日和影响批次 | `更新外部结果` | 查看预计影响、稍后提醒 | 不写入已确认扣减 |
| 失败 | `兑换失败`；显示失败原因是否已核对 | `记录失败结果` | 查看订单、再次记录 | 不自动假定积分已退回 |
| 退款待核对 | `退款待核对`；显示原订单、退款预期日和积分处理状态 | `核对退回` | 查看原扣减、记录争议 | 只有确认退回才生成 reversal |
| 已退款 | `已退款`；显示退回流水及新有效期未知提示 | `查看流水` | 补充有效期、记录争议 | 恢复记录可重算；未知有效期不生成提醒 |
| 已到账 | `已到账`；显示实际到账日、实际价值和来源 | `查看兑换记录` | 记录修正 | 仅此状态确认扣减流水 |

主按钮统一使用“记录兑换”“更新外部结果”“核对退回”，禁止使用“立即兑换”“自动领取”“智能优化”。Cardfolio 不替用户报名、预约、支付、兑换或联系银行。

### 16.4 桌面、移动和提醒中心的操作层级

#### 桌面

- 工作台队列行首显示对象类型和状态，正文显示原因与关键数值，右侧放唯一主操作；查看来源、历史、复制链接和忽略放入次级菜单。
- 详情页顶部固定对象身份、状态和主操作；右侧检查器只用于一次记录或核对，不承载跨对象规则迁移。
- 规则对比、余额与批次差额、兑换影响预览使用完整页面或大面板，保证新旧值和影响范围同屏可读。
- 表格列对齐金额、积分、日期；不以大号数字代替列标题。状态文字与颜色、轨道共同表达。

#### 移动

- 左侧导航抽屉只承担换页；内容详情使用完整页面，单一记录动作使用底部抽屉。
- 抽屉标题包含对象和动作，例如“核对经典白金卡机场权益”，不使用“编辑”或“处理”。
- 抽屉底部主操作固定在安全区内；键盘弹出时可滚动到字段，主操作仍可见。
- 抽屉关闭不能丢草稿；Escape、关闭按钮和遮罩都能退出，关闭后焦点回到触发按钮。
- 抽屉拖拽需 1:1 跟手、可中断、边界渐进阻力；减弱动效时用淡入淡出替代位移。
- 移动概览页提供“年费与任务 / 卡活动 / 卡权益 / 积分与兑换”四个文本入口，横向标签不是唯一发现路径。

#### 提醒中心

每条提醒的最小结构为：`对象类型 + 触发原因 + 对象当前状态 + 截止日 + 主操作`。例如：

> 卡活动 · 奖励待发：经典白金卡活动已达标，预计 2026 年 9 月 5 日发放。主操作：核对奖励。

“完成提醒”“稍后处理”“忽略”只改变提醒记录；用户必须在原对象中记录报名、使用、达标核对或兑换结果。已逾期提醒不会自动移除，已忽略提醒可在历史中恢复。

### 16.5 空、加载、错误、只读与权限状态

| 状态 | 工作台 | 列表/详情 | 主操作与文案 |
| --- | --- | --- | --- |
| 首次空 | 只显示一个“新增第一张卡”主操作；未来模块不占位 | 显示对象说明和一个新增动作 | “还没有卡活动。添加活动后，再记录资格和奖励。” |
| 模块空 | 工作台隐藏该模块摘要 | 说明关联对象和价值，不使用“系统暂无数据” | “这张卡还没有权益。添加卡权益” |
| 筛选无结果 | 保留已应用筛选和结果计数 | 不把无结果误报为数据错误 | “没有符合当前条件的卡权益。清除筛选” |
| 初始加载 | 显示与最终布局相同尺寸的骨架，公告“正在加载工作台” | 模块局部骨架，不遮住已加载内容 | 不用闪烁大号 spinner；加载完成不抢焦点 |
| 局部加载 | 队列可用时，时间线可显示“正在加载” | 失败模块独立重试 | “积分批次暂时无法加载。重试” |
| 保存错误 | 保留队列上下文和草稿 | 错误摘要 + 字段级原因 + 重试 | “未保存：退款日期早于原记录。请检查日期。” |
| 只读/已归档 | 显示只读横幅，不生成新提醒 | 旧规则、周期、流水仍可查看 | “这张卡已归档，历史记录仍可查看” |
| 已过期/已结束 | 只保留尚未核对结果的待办 | 规则和目标只读，可补记结果 | “活动已结束，奖励尚未核对” |
| 无权限/对象已删除 | 不泄露对象名称、ID 或来源 | 返回所属列表或工作台 | “无法访问此记录。它可能已被归档或不属于当前账户。” |
| 网络中断/未知写入结果 | 标记最后成功加载时间 | 保存按钮进入“正在确认”，不重复写入 | “正在确认上次保存结果，请稍候或重试” |

错误状态必须区分“用户输入错误、来源不可信、服务失败、权限不足和外部结果未知”。颜色只做辅助，标题和操作说明原因。

### 16.6 中文文案原则

- 使用对象 + 状态 + 原因 + 动作的句式：`“经典白金卡 · 资格待确认：缺少客群条件。核对资格”`。
- “线索”表示来源尚未证实；“资格待确认”表示用户不能判断是否符合；“报名失败”只表示用户记录的报名结果；“奖励待发”不等于奖励已获得。
- “待入账”只表示用户记录的金额/次数尚未纳入确认值；“暂时达标”只表示按当前记录满足条件；“有争议”表示存在退款、来源或用户核对冲突。
- “待下发”表示权益凭证或服务尚未可用；“可用”需要用户确认资格和周期；“已预约”不等于“已使用”；“现场未使用”不减少次数。
- “余额与批次不一致”同时展示差额；“到期未知”不写成“长期有效”；“退款待核对”不写成“已退款”。
- “处理中”表示外部结果尚未确认；“失败”要显示失败原因是否已核对；“已退款”必须有退回流水；不得使用“自动兑换”“最佳兑换”或“保证到账”。
- 所有日期显示绝对日期，并在需要时补充相对时间；金额、积分和次数必须带单位；估算价值与已确认价值分开。
- 规则预览使用自然语言：“需同时满足：消费 6 次；累计金额满 ¥20,000。”避免只显示 `count_and_amount` 或 `qualified`。
- 来源文案保持中性：“来源：第三方公开资料 · 最后核对：未核对。请在银行官方渠道确认。”不要把官方页面存在写成资格确认。
- AI 相关文案只描述可解释结果，如“按截止日排序”“聚合待处理事项”“规则字段缺失”；不使用“智能判断”“AI 认为”“自动帮你省钱”。

### 16.7 第二轮 UX 验收

以下验收项补充现有 `UX-R2-01` 至 `UX-R2-10`，用于桌面工作台、卡片详情、活动/任务、积分/兑换、提醒中心和移动抽屉走查：

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| UX-R2-B01 | 活动线索 | 列表显示“活动线索 · 待官方核对”、来源和发现日期；不存在“可参加”或“立即报名”按钮 |

### 16.8 验证与残余风险

本轮验证为文档交叉检查：

- 对照 `docs/PRD-WORKBENCH.md` 的实体字段、状态、异常流程、P0 验收和第二轮边界验收；
- 对照本文件既有工作台、卡片详情、活动/任务、权益、积分/兑换、提醒、移动抽屉和可访问性规则；
- 检查所有指定边界均有状态、主操作、次操作、空/加载/错误/只读/权限表现和中文文案；
- 检查工作台未来模块不会替换 MVP 年费事实来源，也不会出现自动银行操作或 AI 资格判断。

残余风险：

1. 状态维度增多可能让列表变得拥挤，需要用真实 3–15 张卡数据验证“生命周期 + 可信度 + 紧迫度”的折叠策略。
2. “暂时达标”“奖励待发”“处理中”容易被用户误读为成功，应在原型中做 5 秒理解测试和屏幕阅读器朗读测试。
3. 退款重开、现场拒绝和退款待核对会增加提醒量，需要验证聚合规则不会让同一对象产生重复待办。
4. 余额与批次差额是正常人工维护现象，不应被视觉设计成系统故障；需要测试用户能否理解“未分配差额”。
5. 移动抽屉承载来源、错误和影响预览时可能出现双层滚动；超过一个短任务或一屏内容应转完整详情页。
6. 权限和归档状态需与服务端所有权校验一致；UX 文案不能替代服务端拒绝访问。

本轮只修改本文件，未改 PRD、架构、数据库、代码或其他文档；未提交、未推送。后续实现前应将 `UX-R2-B01` 至 `UX-R2-B12` 转为桌面 1440/1280 px、移动 390/360 px 的交互走查脚本，并补充键盘、VoiceOver/NVDA、减弱动效、增强对比度和网络失败证据。

## 17. 第五轮信息架构收敛

本轮 UX 复核冻结三层产品边界：当前已实现的年费 MVP（概览、我的卡片、年费日历、提醒中心、设置）；已定义但尚未实现的 P0/P1 活动、权益、积分和兑换；以及 P2 导入、连接器和自动化。没有真实数据时不显示扩展模块空壳导航，也不以 AI 或自动化文案暗示银行资格、兑换或到账。

工作台列表和详情统一使用“对象 + 状态 + 原因 + 下一步”：

- `资格待确认`、`报名待核对`、`奖励待发`、`待入账`、`余额与批次不一致`、`退款待核对` 必须同时展示证据来源、最后核对时间和可执行主操作。
- `处理中` 只表示外部结果未确认；`失败` 保留失败原因；`已退款` 必须有退回流水；`过期` 是已知历史结果，不等于未知。
- 提醒的完成/忽略/稍后处理只改变提醒，不改变活动、权益、任务、积分或兑换事实；来源缺失或日期未知不生成确定性到期/奖励提醒。

桌面端允许比较和深查，右侧检查器只处理一个明确动作；移动端用完整详情页承载跨对象影响，用底部抽屉承载单一记录动作，主操作固定在安全区并恢复焦点。金额、积分、日期、原因和状态文字必须在 360/390 px 不裁切，颜色只作辅助。

验收沿用 `UX-R2-B01..B12`，并新增：活动多卡隔离、积分双差额、兑换三轴和“年费 MVP 与规划模块共存”四项走查。详细规则见 [第五轮 UX 复核](research/CARD-DOMAIN-FOLLOWUP-UX.md)。
